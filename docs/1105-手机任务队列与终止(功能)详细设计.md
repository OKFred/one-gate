# 手机任务队列与终止

## 目标与范围

在既有移动设备状态抽屉增加“任务”页签，展示该手机当前任务与真实优先级队列，并为具备下发权限的管理员提供二次确认的终止操作。使用 One Gate 当前 main 建立 `codex/mobile-task-runtime`；旧 `node_server/dev` 保持归档状态。手机端由 PDA 对话维护，本仓库不修改 `one-autojs6`。

复用 `admin.mobile.async_task:read` 和 `:dispatch`，不增加一级页面、菜单或权限种子。保留既有任务历史状态与终态回调，不能将后台 PENDING 记录冒充手机 QUEUED，也不能因 MQTT PUBACK 就标记 CANCELLED。PostgreSQL 继续关闭尚未适配的 `/admin/mobile/*` 路由。

## 已有机制与缺口

任务历史已包含 taskId、scriptId、priority、创建与开始时间，但没有手机当前队列，几乎没有 RUNNING 写入。已有 MQTT 发布可在 Node 和 Worker 中使用短连接；Node 有 MQTT 结果 listener，Worker 没有长期订阅。现有设备上报已使用 `x-device-token`，可扩展精确 HTTP 路由。

设备 reportedExtra 与 capabilities 每次 info 上报会全量覆盖，不用来保存快照。增加每设备一行的专用快照表，避免改动普通设备 DTO 与所有既有 fixture。

## 手机合同

- 控制 Topic：`autojs6/v2/devices/{deviceId}/task-control`，QoS 1，retain=false。
- CANCEL 精确消息：`{protocolVersion:2,action:'CANCEL',commandId,taskId,createdAt,expiresAt}`。服务端使用 30 秒有效期；手机拒绝 retained、过期或超过五分钟的窗口，按 taskId 与 commandId 幂等处理。
- 状态 Topic：`autojs6/v2/devices/{deviceId}/task-state`，QoS 1、retained；同一快照也通过认证 HTTP 上报。One Gate 首期统一使用 HTTP 接收，保证 Node/Worker 同一闭环，不额外建立第二条 MQTT 快照接入旁路。
- 快照：`{protocolVersion:2,deviceId,timestamp,sessionId,sessionStartedAt,revision,running,queued}`。每项均为 `{taskId,scriptId,priority,createdAt,startedAt:number|null,position:number|null,phase:'STARTING'|'RUNNING'|'QUEUED',cancellable:boolean}`；running 为 null 或 position=null 的当前项，queued 的 startedAt=null、phase=QUEUED。
- 所有时间为 UTC 毫秒。createdAt 是手机实际入队时刻；position 从 1 开始，按真实调度顺序排列，优先级为 HIGH/NORMAL/LOW，同级 FIFO。快照最多 256 个排队项及 256 KiB，不包含任务参数、正文或凭据。
- sessionId 每进程随机生成，sessionStartedAt 固定为该进程启动时刻；revision 在 session 内严格递增。入队、开始、完成、取消、重连及每 15 秒周期均生成新 revision。STARTING 阶段不可取消。
- 手机必须确认仍是目标任务和目标 engine，才可停止；兜底不得误停后续任务。TikTok 等已有外部副作用时，结果保留 outcome unknown / retrySafe=false，不能暗示已撤回发布。

## 服务端接口

均位于 `/api/v1`，所有业务路由使用 POST。

| 路径                                     | 合同与权限                                                                                                 |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `/admin/mobile/async-task/state`         | `{clientId}`，沿用 read；返回 `{clientId,serverTimeUtc,receivedTimeUtc,stale,snapshot,cancellableTaskIds}` |
| `/admin/mobile/async-task/cancel`        | `{clientId,taskId}`，沿用 dispatch；成功仅返回 `{taskId,commandId,status:'CANCEL_REQUESTED'}`              |
| `/admin/mobile/device/report/task-state` | 手机原样快照；使用 `x-device-token` 验证同一启用设备；布尔响应表示是否接纳新版本                           |

snapshot=null 与已上报的空队列不同。新鲜度由服务器接收时间计算，超过 60 秒视为过期，禁用终止。相同 session 的旧/重复 revision，以及旧进程快照不能覆盖新状态或刷新接收时间。客户端时钟倒退、未来时间或不合理序列必须显式拒绝/保留未知，不能靠设备时间伪造新鲜度。

快照表 `admin_mobile_task_runtime` 存 clientId、sessionId、sessionStartedAt、revision、设备时间、服务器 receivedTimeUtc 与受限 JSON。通过一条带版本条件与启用设备存在性条件的 SQL upsert 更新，设备删除时通过 FK cascade 清除对应快照。无数据库默认值。Node SQLite 事务迁移与 D1 新编号迁移只新增该表，保留现有数据与历史迁移。

终止资格由服务器计算：手机明确可取消、快照新鲜、设备有效，且后台存在同设备、同 scriptId 的协议 v2 活动原任务。外部未登记任务、后台已终态任务仍可显示，但明确不可在本站终止。取消服务再次校验，不能只相信按钮或手机的 cancellable。发布只发送指定任务的短期指令，不修改历史终态；原 callback 仍按 taskId/deviceId/scriptId/traceId 与活动态条件保存真正结果。

新终止发布强制验证 TLS，只允许 wss/mqtts，不回退明文；复用现有元数据审计，不记录命令正文。带后台 callbackUrl 的手机任务须以 HTTP callback 成功作为终态已交付依据，不能因另一条 MQTT PUBACK 就清除 outbox；否则 Worker 将永久缺少结果。

## 界面与一致性

页签挂在 DeviceStatusDrawer 现有六个页签之后，使用共享确认框和现有语义色。显示 taskId、scriptId、优先级、状态、入队/开始时间和更新时刻；队列使用快照顺序，不按优先级字符串字典序排序。

读取只在页签激活且文档可见时定期刷新，支持手动刷新。切换设备、关抽屉、离页或切账号清空状态并取消旧读取；晚到结果不得覆盖新目标。无快照、空队列、过期快照与读取失败分别显示，不能补造运行状态。

终止使用破坏性确认，确认返回后重新核对身份、设备、权限、快照与请求锁。双击只发一次；不自动重试写入。明确成功仅提示“终止请求已发送，等待设备确认”；超时或不确定服务端错误保留结果未知，手动刷新确认。请求结果与列表刷新分开，已发送后刷新失败不能改称发送失败。

## 验证与交付

实施前后记录 server/admin TypeScript 诊断。覆盖严格输入、设备令牌/停用设备、跨设备任务、旧 session/revision 重放、长任务心跳、新鲜度边界、MQTT retain/过期时间、终态不覆写、未知结果及权限。Node 与原生 Worker/D1 均验证；新增迁移覆盖幂等和失败回滚；前端用隔离夹具覆盖队列、权限、二次确认、双击、目标/账号切换与乱序。

与手机端用合成任务联调，不触发真实 TikTok 发布或终止生产业务。代码、迁移演练、模拟链路与真实设备/生产验收分别记录。完成构建、格式与 diff 检查后交付未提交的开发分支；提交、推送与生产发布等待明确授权，并在提交前执行秘密扫描。
