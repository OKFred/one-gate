# 外部身份统一迁移与数据库配置化计划变更

## 当前基线

- 基线分支为最新 `origin/dev`，本任务分支为 `codex/external-auth-via-one`，不使用 worktree。
- Hodor 现有 SSO 已实现 OIDC Authorization Code + S256 PKCE、显式账号绑定和 TOTP 后置门禁。
- SSO 连接由五个 `SSO_*` 环境变量提供；PKCE verifier 使用 `OAUTH_SENSITIVE_DATA_KEY`。
- Hodor 仍直接暴露 GitHub、飞书和微信 WIP 登录表面，并在资料接口返回 OAuth 绑定。
- 修改前 server TypeScript 有 6 个与 mobile Repository/脚本有关的既有错误；admin 前端 build 通过。

## 实施阶段

### 1. 配置契约与持久化

- 在 SSO domain/application 定义连接、状态、版本和配置管理用例。
- 新增 `system_sso_connection` Drizzle model、SQL DDL、Node migration 和 D1 append-only migration。
- 扩展 D1 Schema Contract，验证字段、索引和无外键。
- 增加 Drizzle Repository 和并发条件更新测试。

检查：SSO domain/application/repository Vitest、migration 测试、D1 deployment contract。

### 2. 配置 API 与兼容桥

- 增加 config get/save/test/disable 的 Schema、纯 API 对象和错误映射。
- Discovery/JWKS Probe 复用现有 OIDC 出站适配器的安全 fetch 与日志约束。
- 运行时改为数据库优先；仅配置表为空时读取完整旧环境配置。
- 增加 `HODOR_AUTH_MASTER_KEY`，兼容期允许旧根密钥名称回退。

停止条件：数据库配置未通过 test、解析结果与旧配置不一致或发现敏感日志时，不进入下线阶段。

### 3. 下线 Hodor 直连外部身份

- 从 auth service 移除 OAuth 和微信 API；删除活动 OAuth application/infrastructure/interfaces 代码。
- 清理 user repository/service 中仅供直连 OAuth 使用的方法，但保留 legacy Drizzle Schema。
- 删除前端 OAuth callback、Provider 按钮、档案弹窗和独立 API 封装。
- 用户资料移除 `githubUsername`、`oauthBindings`，同步生成 OpenAPI 类型。
- 调整匿名路由与 TOTP 白名单，仅保留密码、SSO、TOTP 和现有机器路由。

检查：auth HTTP 对象、白名单、密码/SSO/TOTP、前端登录/资料/callback 和 JSON 404 回归。

### 4. 最终配置收口

- 从 `.env.example`、Wrangler required vars、worker types、CI 和部署脚本删除五个 `SSO_*` 及
  GitHub/飞书 Provider 配置。
- 最终运行时只读取 `HODOR_AUTH_MASTER_KEY`；旧根密钥名称保留到观察期结束后再删除。
- 增加静态检查，禁止活动源码重新引用 `GH_*`、`FEISHU_*`、`SSO_*` 或 legacy OAuth Repository。

检查：Worker types、Wrangler dry-run、workflow/config contract 和敏感信息扫描。

### 5. 验证与记录

- 运行 server 受影响 TypeScript、定向 Vitest、admin build、OpenAPI 生成及变更文件 ESLint/Prettier。
- 对比修改前 6 个既有 TypeScript 错误，确保本任务未新增诊断。
- 执行 `git diff --check`、LF/UTF-8/BOM、无新增 `any/as any` 和 legacy 表写入检查。
- 最多完成五轮复盘并补实际落地文档，区分代码、Mock、本地、staging 和 production 证据。

## 发布顺序

1. one staging 先完成 Provider Connection、租户策略和 Hodor OIDC Client 的数据库配置与验收。
2. 部署 Hodor 兼容桥和 migration；使用本地管理员 + TOTP 写入并测试 SSO 数据库配置。
3. 验证数据库配置与旧环境配置行为一致后，部署数据库独占和 OAuth 下线版本。
4. staging 稳定后再请求 production migration/deploy 确认。
5. 旧应用撤权、旧 Secret 删除和 legacy 表物理清理另开迭代。

任何远程 D1 migration、Secret 上传、Provider 应用创建、PR 合并和 production 部署均在对应门禁满足后
单独执行，不与代码提交混合。
