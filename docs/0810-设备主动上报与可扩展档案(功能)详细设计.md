# 设备主动上报与可扩展档案详细设计

## 目标与边界

- 复用 `/admin/mobile/device` 业务命名空间和 `#/admin/mobile/device` 页面，不新增一级菜单。
- Node 通过 MQTT 消费设备上报，Worker 通过带设备令牌的 HTTPS 接收相同协议。
- `DeviceAppDrawer` 保持“仅下发安装”，不恢复 App 信息采集或同步。

## 上报协议

| 类型         | MQTT Topic                               | HTTP API                               | 行为                                                    |
| ------------ | ---------------------------------------- | -------------------------------------- | ------------------------------------------------------- |
| Presence     | `autojs6/v2/devices/{clientId}/presence` | `/admin/mobile/device/report/presence` | 60 秒一次，retained；只包含在线状态与时间               |
| Device Info  | `autojs6/v2/devices/{clientId}/info`     | `/admin/mobile/device/report/info`     | 进程启动采集一次并缓存；重连只重发缓存                  |
| Device Event | `autojs6/v2/devices/{clientId}/events`   | `/admin/mobile/device/report/event`    | 电量/网络变化及短信/通知事件；`clientId + eventId` 幂等 |

协议版本为 2。服务端校验 Topic 与载荷中的 `clientId/deviceId` 一致；HTTP 使用 `X-Device-Token`，只接受已登记、启用且令牌有效的设备。MQTT Will 的离线 Presence 可立即落库，常规在线判定为最后心跳不超过 150 秒。

## 数据模型

`admin_mobile_device` 保留管理字段并增加：

- 设备快照：厂商、品牌、型号、Android/SDK、AutoJS6/客户端/协议版本、电量、充电、网络、脚本能力。
- Presence：上报状态、最后心跳、最近上线/离线时间。
- 敏感标识：IMEI 脱敏摘要与 AES-GCM 密文、序列号脱敏摘要与密文。
- 上报令牌：仅保存 SHA-256 摘要。
- 扩展数据：`reported_extra_json`、`custom_metadata_json`、`custom_sensitive_metadata_ciphertext`。

新增 `admin_mobile_device_event`：`event_id + client_id` 唯一，保存事件类型、设备事件时间、非敏感摘要、敏感载荷密文和创建时间；保留 30 天。

## 扩展字段约束

- `reportedExtra` 仅可信设备上报更新；`customMetadata` 仅管理员更新。
- 每个区域最多 50 个键、UTF-8 JSON 不超过 32 KiB、最大嵌套深度 3。
- 键名采用 `^[A-Za-z][A-Za-z0-9_.-]{0,63}$`；值限定为字符串、有限数字、布尔、ISO 日期字符串、空值、简单数组或深度不超过 3 的普通对象。
- 保留字段及包含 IMEI、序列号、令牌、手机号等敏感语义的键拒绝进入 `reportedExtra`。
- `customMetadata` 每项为 `{ value, sensitive }`；普通值存 JSON，敏感值整体 AES-256-GCM 加密，列表/详情只显示占位符，单独 reveal API 需要 `admin.mobile.device.view`。

## 加密与密钥

- Node 与 Worker 共用 Web Crypto：AES-256-GCM、随机 96-bit IV、字段级 AAD，密文格式 `v1.<iv-base64url>.<cipher-base64url>`。
- `MOBILE_SENSITIVE_DATA_KEY` 必须解码为 32 字节；缺少或无效时，敏感设备信息、短信/通知正文和敏感自定义字段拒绝持久化。
- 日志只记录 clientId、事件类型、eventId 和处理结果，不记录令牌、IMEI、序列号或消息正文。
- 上报令牌使用 32 字节安全随机数，明文仅在生成/重置响应中出现一次，数据库仅保存 SHA-256。

## 服务端流程

1. 接收 MQTT/HTTP 后完成结构校验、设备存在/启用校验和（HTTP）令牌校验。
2. Presence 原子更新在线时间；Info 加密敏感标识并更新快照；Event 先构造安全摘要，再按唯一键插入。
3. 列表响应依据 `lastHeartbeatTimeUtc` 与 150 秒阈值计算有效在线状态。
4. Node 每天执行事件清理并周期校正超时离线；Worker scheduled 同时执行任务超时、设备离线校正和 30 天事件清理。

## 管理端

- 列表展示在线、设备/Android、客户端版本、电量、网络、最后心跳；支持在线状态筛选。
- 页面可见时每 30 秒静默刷新，保留分页、筛选和当前数据。
- “设备状态”抽屉含概览、扩展信息、事件三个页签。事件页签打开时每 10 秒刷新并支持事件类型、时间筛选。
- reveal 与令牌生成/重置为独立操作；令牌用一次性结果对话框展示。

## 兼容与降级

- 静态属性采集失败以 `unavailable` 状态上报，不影响进程与其他字段。
- IMEI 多卡读取后去空、去重；手机端从不记录标识内容。
- 旧任务协议与 MQTT Topic 保持不变；新增 `/info` 订阅不影响已有任务结果。
- Worker 不建立 MQTT 长连接，仅提供 HTTP 和 scheduled 能力。
