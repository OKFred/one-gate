# 天地图内嵌：详细设计

## 目标与范围

从最新 `main`（8daae8de）创建 `codex/tianditu-map`。上一轮首页体验改动已合并。本轮增加可供登录用户使用的天地图工作区，复用已有地图服务能力，不移植旧项目的地块、绘图和其他业务数据。

首页增加短入口，地图工作区使用 `/#/home?view=map`。地图与用量总览分别挂载，返回首页时销毁地图；不增加侧栏菜单，不扩大现有路由权限豁免，不新增可分配权限或数据库种子。普通登录用户也可打开，不依赖 Cloudflare 用量权限。

## 配置与认证

新增 `POST /api/v1/admin/base/map/config`，请求 `{}`，响应数据为 `{ configured: boolean, browserKey: string | null }`。通过现有 encapsulation、登录及二次验证中间件，明确 `permission: false` 只表示不额外要求业务权限，不表示匿名接口。业务层再次要求 `principal.kind === 'user'`，拒绝 API Token。空配置或格式不合法时返回未配置及 null，不回显原始内容。

服务端从 `TIANDITU_BROWSER_KEY` 读取 32 位十六进制浏览器 Key，Node 使用环境配置，Worker 使用部署 Secret。只下发这一项经过校验的浏览器配置，不开放任意配置读取。接口设置 `Cache-Control: private, no-store`，禁止 CDN/浏览器缓存；不把 Key 写入业务日志、错误文案、源码、测试快照或静态制品。PostgreSQL 仅新增此无业务数据库依赖的模块支持。

旧项目归档中发现非空 Key，自有 one-code 与 node_server 未找到非空配置。归档来源的使用权及域名限制需确认，确认前不复制或调用该 Key。缺少可用 Key 不妨碍实现及隔离测试，真实供应商验收单独记录。

浏览器 Key 会出现在实际瓦片请求中。登录接口防止匿名取得配置，不把浏览器 Key 描述成对已授权浏览器不可见的服务端秘密。供应商域名限制仍需核验；本轮不修改供应商账号、授权范围或创建新凭据。

## 地图展示与生命周期

使用本地打包的 Leaflet 稳定版作为地图视图，接天地图官方 HTTPS WMTS，固定供应商域名与图层，采用 Web Mercator 瓦片矩阵。初期提供矢量/影像及对应注记、缩放、比例尺、回到初始视野。初始为全国视野，不请求用户定位，不带入旧业务坐标或私人位置。

地图页挂载且仍处于原登录会话时才请求配置，明确 `ok: true` 且配置有效后才建立地图和发起瓦片请求。未配置、读取失败、瓦片加载失败及超时分别呈现简短局部提示和手动重试；至少有真实底图瓦片加载后才报告地图可用，不能把脚本或组件挂载当成供应商成功。

请求采用 AbortController、代际及会话检查；返回首页、离页、退出、换账号均取消未完成请求并销毁图层与地图，清理 ResizeObserver、监听器及超时回调，丢弃迟到响应。不在 localStorage、sessionStorage 或跨会话模块缓存中保存 Key。请求错误沿用共享认证与二次验证处理，其他错误局部提示一次。

采用 MUI 语义化主题和中英文文案，地图尺寸适配窄屏，保留天地图来源标注。地图交互支持键盘，不在首页预加载地图或消耗瓦片额度。

## 验证与交付

认证测试覆盖匿名、无效登录、API Token、登录用户、未配置、无效配置、缓存头和额外字段拒绝。Node 与 Worker 验证端点认证及响应合同，PostgreSQL 核对精确能力边界。

浏览器隔离测试使用模拟配置和瓦片，覆盖首页不预取、打开/返回、普通用户、图层切换、瓦片失败与重试、迟到响应、登出/换账号、窄屏和键盘。服务端、前端执行修改前后 TypeScript 对比、变更文件格式/lint、相关测试、构建与 `git diff --check`，完成多轮复核和实际落地文档。

真实 Key 验收必须使用获得确认的配置，与模拟测试分开；公开仓库不包含其来源路径、内容或供应商原始请求。上线沿用现有 PR/CI 和保留 D1 数据的发布方式，不执行全量初始化。
