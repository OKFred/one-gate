## 实施与验收顺序

1. 从最新 dev 建分支；收集六组类型基线；隔离复现不修改生产状态。
2. 输出设计和本文后，先确定公共会话工具，再分工认证边界、HTTP／路由守卫和 E2E。
3. 变更格式修复和类型比较，独立复盘；若需修正，先暂存当前版本再改。
4. 运行现有认证 8 项、回收站 39 项及新增用例，三端构建；不为无服务端代码变化重复本地 SQL／迁移演练。
5. 补实际落地记录，提交 PR，CI 通过后合入 dev；核对自动发布和真实只读页面。

本轮不新增权限、API、OpenAPI、数据库字段或迁移。已确认但独立的后续问题：禁用角色不应继续贡献鉴权权限／数据范围，但管理界面要保留绑定且部门删除仍须阻止其引用；清理执行器可独立启动资源，减少单资源长期 pending 对后续资源的阻塞。
