# 个人资产在线状态接入契约

日期：2026-11-08。本文区分本轮实际行为和未来接入建议，不代表真实采集链路已经接通。

## 当前边界

本轮个人资产使用企业台账的 `assetId`，位置映射只属于当前账号。真实资产统一返回 `presenceSource=unconfigured`、`status=unknown`、`basis=not_connected`，心跳、观察和失效时间全部为 `null`。响应生成时间仅说明请求何时完成，不能证明设备在线。

源侧已有 presence 事件模型、受登记范围约束的 PostgreSQL reader 和时间线计算代码；没有可直接复用的只读 HTTP 接口。本轮尚未接通真实 presence，也未完成部署验收。旧温度数据新鲜、队列清空或服务健康均不能替代设备在线证据。

登记中没有已批准的 One Gate UUID 关联，也没有可用于两个展示区域或楼层的可靠位置字段。本轮不启动额外订阅，不连接生产 reader，不修改源身份、源区域、采集标记或挂载历史。后续授权、云表权限、费用、额外连接与容量调整须独立处理。

演示由用户显式进入，使用合成身份和合成证据，并持续标明“演示”。请求失败不得自动切换演示，也不得将演示计数混入真实资产。

## 未来最小投影

接入时继续使用个人资产 overview，不让浏览器指定物理表、SQL、源设备身份或订阅主题。后端先核验登录身份、企业和资产权限，再通过私有批准映射读取既有 registry-scoped reader；不另建 MQTT 采集链路。

源身份与展示位置分别映射。UUID 外观、名称、地址、温度通道不能作为自动匹配依据。位置未确认时保持待定位，不能从源 `site_id` 推导住宅、楼层或房间。

以下为后续接入字段建议，本轮没有开放 live 分支：

| 字段                            | 语义                                                                                  |
| ------------------------------- | ------------------------------------------------------------------------------------- |
| `presenceSource`                | `unconfigured`、`unavailable` 或 `ready`，反映源配置和读取能力，不代表设备状态。      |
| `asOfUtc`                       | live 模式为源端实际状态计算时刻；本轮 unconfigured 仅为响应时刻，不能用于在线判定。   |
| `assetId`                       | 已授权企业资产 UUID；源端身份只保存在私有批准映射内。                                 |
| `presence.status`               | `online`、`offline`、`lost` 或 `unknown`。                                            |
| `presence.basis`                | 稳定、白名单化的判定依据；不按翻译后的文案匹配。                                      |
| `presence.lastHeartbeatTimeUtc` | 最近一次有效在线证据的服务端观察时刻；不是设备自报时钟，也不是查询时间。              |
| `presence.observedTimeUtc`      | 源 `last_observed` 的服务端观察时刻，表示最后状态证据；不是包装响应生成时间。         |
| `presence.expiresTimeUtc`       | 源端给出的本次状态保证上界；无法可靠计算时为 `null`，该快照不能作为可缓存的实时状态。 |

时间统一为 UTC 毫秒的有效安全整数，缺少证据时为 `null`，不能补零或当前时间。若增加 `generatedAtUtc`，只能表示包装时刻，不得刷新原 `asOfUtc`、观察时间或有效期。不得下发真实地址、源设备／报告者／会话身份、订阅主题、凭据或原始事件。

## 状态语义

源状态只有 `online/offline/unknown`；`lost` 是展示层对明确依据的细分，须与源端现有面板一致：

| 源状态与依据                                                     | 展示状态  | 含义                                                 |
| ---------------------------------------------------------------- | --------- | ---------------------------------------------------- |
| `online`，新鲜有效心跳或直接读取，观察覆盖与祖先依赖均有效       | `online`  | 当前有在线证据。                                     |
| `offline + lwt_observed/shutdown_observed`                       | `offline` | 已观察本次会话遗嘱或主动退出，不进一步推断断电原因。 |
| `offline + heartbeat_expired/read_failed`，观察覆盖仍有效        | `lost`    | 有效观察期间心跳超时或直接读取失败，失联不等于关机。 |
| 观察链路中断、祖先未知或会话变化、仅缓存、没有证据、来源读取失败 | `unknown` | 不能可靠判断设备当前状态。                           |

未知依据包括 `no_observation`、`observer_unknown`、`parent_unknown`、`parent_session_changed`、`cached_only`、`dependency_cycle` 及等待有效新会话的状态。未识别或不一致的状态／依据组合保守降为未知，不猜测离线。

隐藏依赖先参与计算，再从物理设备清单和计数中排除。代理设备必须有新鲜直接读取且父依赖有效；缓存值不能证明物理设备存活。两地动画连线只表达拓扑示意，不表达网络健康。

## 新鲜度与缓存

现有时间线函数没有直接返回完整失效上界。未来适配器需沿用源端状态机，综合当前状态所需的观察覆盖租约、祖先依赖及在线证据 TTL，返回可信 `expiresTimeUtc`；不能只用本人最后心跳加固定时间。

对 `lost` 状态，本人的心跳 TTL 已经过去，不能再次把它作为未来失效上界取最小值；应依据仍然有效的观察覆盖与祖先依赖计算。算不清上界、源读取滞后或结果已过期时，返回未知而非临时延长有效期。

快照按半开有效期处理：未到上界才可沿用，恰到上界即降为未知并等待重新计算。客户端可以保守降级，不能凭浏览器计时自行从在线改判失联。悬停、重渲染、包装响应、重试、后台标签恢复均不延长证据有效期；时钟变化不能使旧结果重新有效。

读取失败时可保留明确标注的历史观察时间，但不得把旧状态显示成当前在线。历史遥测推断只属于其限定历史区间，不能填补当前 presence 缺口。retained、重放、旧会话、重复／倒序事件与异常未来时钟不能刷新在线证据。

## 接入与测试门槛

后续真实接入前，分别提供以下证据：批准的私有资产映射、真实事件及接收覆盖、受限 reader 的有效权限、源端状态计算时间和可靠失效上界。源端表可读不等于完整链路验收通过。

定向测试至少覆盖：

1. 未配置、映射缺失、空事件、源失败和过期均为未知，证据时间不伪造；演示与真实数据不会互相回退。
2. 有效期内、恰到上界、后台恢复和时钟变化；响应重新包装不续命。
3. 心跳超时／读取失败为失联，遗嘱／主动退出为离线；观察覆盖失效优先变未知。
4. 父依赖失效或会话改变、缓存设备、隐藏依赖计数；本人 TTL 已过期的失联状态仍以有效覆盖决定其保证上界。
5. retained、重放、旧会话、同毫秒事件顺序及未来时钟，不得制造新鲜在线证据。
6. 企业和账号隔离、权限撤回、身份切换、查询乱序；不下发源身份或私有映射。

本文进行了两次只读语义核对：源端状态机／reader，以及现有面板的状态映射。本轮没有连接生产 presence reader，没有修改源端配置或进行硬件验收；这些仍为后续接入门槛。
