# Cloudflare 用量首页与 AI 对话统一：实际落地

## 范围与分支

开发分支为 `codex/cloudflare-usage-dashboard`，基于实施时最新 `main` 的 `94318dc4`。先完成详细设计和计划变更，再实施。本次交付分开记录代码验证、迁移演练、真实账号只读联调和上线结果。

## 已落地行为

- 首页移除重复 AI 实现，对所有登录用户提供欢迎信息和有权访问的快捷入口。获授用量读取权限时展示 Cloudflare 同步状态、按币种/账期/费用口径分组的官方费用、产品指标、7/30 天趋势、逐项明细和覆盖原因。
- AI 统一在 `/admin/ai/chat`：保留 Markdown、代码块、复制、单会话附件、快捷问题、重试、新会话和页内展开；新增同读权限的模型清单和可选 `modelKey`。实际模型及供应商在请求前确定，只调用一次，失败不切换。配置修订变化明确冲突，公钥不包含凭据哈希。
- 图片验证当前输入与完整历史：只允许一张 PNG/JPEG、解码后不超过 5 MiB、校验文件签名和模型能力。重试使用原问题、历史、附件和模型快照；双击、清空、离页、身份变化均有并发保护。
- Cloudflare 模块使用两个独立的 account-owned 只读 Token，限定官方 API 地址；订阅、计费和 Analytics 分别探测。官方计量不按产品白名单过滤，所有无法确认的额度保持 `null`，不自行估价。
- 最近成功来源快照、90 天逐日历史、同步 cursor/租约存于三张表。账号隔离、带代际校验的租约、条件写入、幂等发布和原子读取避免并发污染；分页未完成不发布完整统计。来源失败保留旧成功值并明确过期。
- 现有 Node/Worker 分钟入口接入用量维护，包含 PostgreSQL 分支；15 分钟周期申请采集，手动刷新合并并按账号限流。单次任务有步骤和时间预算，后续 tick 续跑；失败和汇总只记录元数据。
- 权限为 `admin.maintenance.cloudflare_usage:read/update`，新增默认授权仅角色 1。同步业务标识、双语后端翻译、OpenAPI 和前端权限常量；PostgreSQL 只新增开放用量路由。

## 迁移与结构演练

| 后端        | 交付与验证                                                                                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SQLite/Node | 专用事务脚本 `migrate-cloudflare-usage.ts` 应用 0018+0019，结构、种子、标记原子提交；校验 checksum、重复执行、已有无标记表和漂移；验证失败回滚、原数据和自增高水位保留。 |
| Worker/D1   | 新增编号 0018（结构）和 0019（权限/翻译），以及定向生成的新库 DDL/只读结构契约。真实本地 D1 验证重复 DDL、权限只授角色 1、索引冲突回滚及结构漂移。                       |
| PostgreSQL  | 新增 0002，旧 0001 的字节和 checksum 保持不变。迁移器验证连续历史和原结构指纹后顺序升级；独立本地 PG17 验证旧账本升级、新库安装、并发、重复、漂移、未知账本及失败回滚。  |

生成器只处理三张明确注册的表和两份契约，不清理历史迁移目录。Node 工具拒绝已有用量表但缺本工具成功标记的数据库，不会自动接管来源不明的结构。操作步骤见 [Cloudflare 用量说明](./cloudflare-usage.md)。

复核发现并修正了旧账期缺结束时间被误当本周期、不同周期计量合并、费用口径混加、共享额度重复确认、订阅顺序影响套餐判断，以及角色 1 权限计数未同步等问题。全局集成复核三轮；前端五轮、用量后端四轮、AI 与 PostgreSQL 迁移各两轮，各范围均控制在仓库规定的最多五轮内。

## 真实账号只读联调

两枚 Token 由用户确认创建，值仅保存在用户指定的仓库外私有环境文件。通过官方 verify 验证有效；探测及采集仅调用只读接口，不修改账号订阅、计费设置、业务数据库或生产绑定。

官方订阅、V1 计费及 Analytics 数据已取得并与官方可计费使用量页面核对 R2 的账期、单位、数量和官方费用。V2 使用量返回 403，费用入口返回 405，能力限制如实进入覆盖状态；没有用本地价格反推。Workers Free 在官方面板可见，但当前公开订阅返回未提供该套餐，因此程序继续保持套餐/相应额度未知，不把人工观察写成默认规则。

最终真实采集使用 22 次只读 HTTP、两个有界 tick（约 13 秒及 9 秒），取得 8 项指标、3 项官方费用和 162 条逐日历史。按当前订阅账期核对三项 R2 配额；其他无法确认的套餐与字段继续显示未知。上述统计数量用于说明覆盖，不代表所有 Cloudflare 产品均已完整覆盖。

覆盖清单、脱敏数量核对和真实请求状态保存在仓库外验收报告中，公开文档不包含账号 ID、财务原始响应、凭据或私人账单信息。Workers AI neurons、Browser Run 等只接受官方计费记录；没有已验证的专用指标时明确标注覆盖限制。

## 计划差异、上线状态与剩余项

- 为兼容既有 PostgreSQL 的原 0001 账本，补了有序迁移器与测试 helper；没有改写历史迁移。
- 多订阅共享额度不能明确归并时保守显示未知并附原因，避免重复计算额度池；不同费用口径不相加。
- 实际 Alpha API 能力受账号限制，完整产品覆盖不能由本次代码保证；面板使用逐来源覆盖清单表达可获取范围。
- 真实视觉模型推理尚未执行。Cloudflare 首次模型许可仍由用户自行接受，受控图片测试不代表真实模型验收。
- 实现阶段完成后，用户授权提交推送、创建 PR，并在检查通过后合并 `main`；远端 CI 与合并结果以对应 PR 为准。生产迁移和部署仍是独立的后续范围，上线前按操作说明升级数据库、配置三项 Secret，再做已登录用户权限与真实数据验收。
- 没有本轮新增但待用户决策的 TypeScript 错误。后续应根据公开 API 能力变化扩充经过验证的产品适配器与额度规则，并在 Token 到期前更新私有配置。
