# 前端本地化翻译迁移（优化）实际落地报告

## 落地概述

已全面完成前端本地化多语言翻译架构改造，将全部静态 UI 文案从后端 SQLite 数据库 / 模块 `translation.ts` 迁出，移至前端 TypeScript 文件进行模块化集中管理。同时保留了后端接口 `listAll` 覆盖本地文案的高优先级热修复能力。

---

## 改造成果与变化对比

### 1. 新功能开发流程对比

| 环节 | 改造前 | 改造后 |
|---|---|---|
| **文案添加** | 需在后端对应 package 的 `translation.ts` 中声明 | 直接在前端对应 `locales/[lang]/[namespace].ts` 声明 |
| **生效流程** | 需重新跑 `pnpm run db:init node` 写入 SQLite，启动前端等待接口拉取 | **无需后端任何操作**，修改前端保存即生效 |
| **网络开销与体验** | 页面加载必须等待 HTTP 接口返回全量翻译（有白屏/闪烁） | **同步加载本地 TS 字典**，冷启动零延迟；接口后置异步 merge 热修复 |
| **后端 shared.ts 体积** | `1757` 行（大量混入 UI 与特定页面文案） | **大幅精简至仅保留后端异常报错** (`errorHandler.*`) |

## 优化后的目录与架构规范

### 1. 跨 App 共享层 (`platform/packages/ui/src/locales/`)

集中管理所有 App 通用的词汇、动作、UI 状态、侧边栏菜单及全局认证词汇：

```
platform/packages/ui/src/locales/
  ├── zh-CN/
  │   ├── common.ts     # 纯通用动词 (cancel/confirm/save/delete/edit/view...) 与网络层错误
  │   ├── components.ts # UI 组件通用文案 (表格/列名/表单/筛选器/弹窗/分页...)
  │   ├── sidebar.ts    # 全局导航侧边栏菜单与 businessType 映射
  │   ├── auth.ts       # 登录、注销、修改密码、通用审计日志
  │   └── index.ts      # 聚合导出
  └── en-US/ (对应英文字典)
```

### 2. App 专属页面层 (`platform/apps/[app]/src/locales/`)

各前端 App（`admin`、`enterprise`、`personal`）独立管理页面特定文案：

- **`platform/apps/admin/src/locales/`**：包含 system、home、mail、maintenance、ai、swarm、i18n、oss、rpa、data 等模块页面文案。
- **`platform/apps/enterprise/src/locales/`**：包含 workflow、attendance、edm 模块页面文案。
- **`platform/apps/personal/src/locales/`**：包含 profile (含性别枚举) 等模块页面文案。

### 3. 双层文案加载机制 (`useLoadTranslations`)

```typescript
// ① 同步写入本地共享文案（立即可用，无需等待 HTTP 接口，解决白屏）

setIsLoaded(true);

// ② 异步合并后端热修复文案（接口数据优先覆盖本地字典）
const response = await listAllFn({ data: { isEnabled: true, application: 'frontend' } });
```
