# 微前端入口缓存修正

发布健康页时，普通刷新仍显示旧界面。浏览器网络记录确认固定地址 `/remoteEntry.js` 使用 `public, max-age=14400, must-revalidate`，并从磁盘缓存读取旧模块入口；临时禁用页面缓存后，新健康页及中文文案正确显示。首页 HTML 已使用零秒缓存，带哈希资源无需改变。

共享 `platform/public/_headers` 为 `/remoteEntry.js` 增加与版本文件相同的禁止缓存头，三套前端均携带。此修改不改变业务代码、API、权限、数据库或带哈希静态文件的缓存策略。已经留存在浏览器中的旧响应无法追溯修改，本轮工作页需要强制刷新后验收。

本次为单个静态响应配置修正，完成两轮源文件与范围复核、UTF-8/LF/空白检查；原版本的完整 Node、Worker、浏览器、类型及秘密扫描证据分别保留，业务源文件未变化，不将复用证据记成重跑。正式制品须从合并后的 main 重建，并独立记录部署版本、实际响应头与页面验收结果。

没有新增 TypeScript 文件或诊断。后续若需要让所有仍持有旧入口缓存的客户端立即更新，可另行评估构建版本绑定的入口地址；本次不引入时间戳请求或额外版本配置。
