# TOTP 门禁路由误重检修复实际落地

## 问题与根因

生产管理端完成主认证和 TOTP 后，点击内部菜单虽然仍是 HashRouter 导航，但共享
`AuthenticationBoundary` 会再次进入 `CHECKING`。这会临时卸载菜单、权限和布局，
重新请求门禁状态、Token、菜单及按钮权限，用户体验接近整页刷新。

根因是鉴权评估函数直接依赖当前 pathname 和 React Router 返回的 `navigate` 函数。
声明式路由导航后这些依赖会变化，挂载鉴权监听器的 effect 因而重新执行。

## 实际改动

- 使用 ref 保存最新 pathname，使鉴权事件仍能读取当前回调路径，但普通路由变化不再
  重建鉴权评估函数。
- 使用 ref 保存最新 `navigate` 函数，避免其引用变化触发鉴权 effect 重跑。
- TOTP 已验证且需要从登录页进入主页时直接切换为 `READY`，不再通过第二次
  `CHECKING` 完成导航。
- 扩展既有 Mock OAuth/TOTP Playwright 用例，验证 `/home → /me → /home` 期间：
  - 同一个布局 DOM 节点保持挂载。
  - gate status、Token check、菜单和按钮权限请求计数均不增长。
  - 真正刷新页面后上述初始化请求会重新发生。
- Mock 预览不提供 enterprise/personal remoteEntry；用例仅屏蔽该环境下无关的单次
  chunk 自愈刷新，未修改生产 chunk 恢复逻辑。

## 范围约束

本次未修改 Sidebar、HashRouter、路由表、微前端加载、预取或页面缓存；未修改后端
接口、TOTP 协议、Cookie、数据库、Cloudflare 配置或生产资源。
