# 回收站身份隔离实际落地

## 实现结果与范围

从最新 dev a4f8017e 创建 codex/recycle-bin-auth-isolation。本轮用回收站复现并修复公共认证层的跨标签身份归属：旧确认会使用新凭据、旧普通 401 关闭回调会清除新登录、旧 TOTP 401 会打断已验证的新会话。修复覆盖三端共用 UI；没有改变 30 天期限、资源注册、部门适配器、服务端权限或数据库结构。

auth 工具共享当前存储快照和已提交页面会话。正常登录／退出先轮换独立随机标记，随后写用户资料；同步核对凭据和标记，跨标签事件再补偿旧版本写入的身份转换。同 token 更新资料不轮换会话。页面通过 useSyncExternalStore 观察身份，变化时卸载旧业务树，layout 阶段提交新页面归属，再启动 gate 校验。菜单和权限随新业务树重新加载。

HTTP 调用同步捕获页面会话，发出前与成功／失败响应先检查归属。旧响应和取消不触发全局通知、二次验证事件或新请求中止，ignoreAbort 也不能跳过归属检查。延迟 401 提示关闭、ProtectedRoute 校验与 profile 写回、验证页退出和普通顶栏退出均检查原会话。URL 转移凭据不会覆盖已有的不同身份。

## 与计划的差异及复盘

完成 2 轮交叉复盘。第 1 轮发现普通 Topbar 退出仍在 finally 中无条件清理新身份，增加该文件的退出与语言写回守卫，并清理相应重复错误输出；第 2 轮复查通过。其他应用文件符合计划，没有改生成权限、API 定义或 OpenAPI 类型。

前置设计中的本页代次进一步补上独立存储标记及已提交视图归属，分别覆盖事件未送达的正常 A→B→A 和旧页面尚未卸载时的提交窗口。共享状态放在同一页面的 Symbol.for 运行对象中，当前联邦应用只暴露 AppContent，无需多根边界管理器。

格式后的首轮类型比较发现 HTTP 泛型适配 TS2322，先暂存再修正，复查后无新增诊断。认证 E2E 首轮有 3 项因 fixture 的远程模块加载失败触发自动刷新而失败；补齐已有测试采用的远程模块 mock、一次性身份初始化后全套通过，保留原始失败日志，没有调整应用来迎合测试。

## 发布验收与后续边界

合入 dev 后核对 Worker 健康／版本、三端 Pages 版本和实际引用的认证脚本，并在已有登录的线上回收站执行只读查看／刷新。不切换真实用户、构造生产异常或创建／恢复／清除业务记录。

这是客户端状态归属隔离，不能回滚已执行的服务器写入，也不能阻止浏览器处理已返回的 Set-Cookie。尤其共享 gate cookie 可能被迟到的退出响应清除，此时下一次请求仍须按服务端要求重新验证；本轮只保证旧退出续体不会清空新本地身份或导航。nonce 与 userInfo 的两次写入不是事务，短暂中间状态允许拒绝／重检；不带标记的旧版本或原始存储写入，其 ABA 在事件到达前无法同步识别。旧版本标签需刷新才获得本轮机制。

独立后续项：禁用角色应从鉴权权限／数据范围计算中排除，同时保留管理界面绑定及部门引用保护；清理资源可分别启动，减少单资源长期 pending 阻塞其他资源。备份删除重放、外部清理告警与其他业务资源迁移继续分别治理。本轮没有新增待处理 TypeScript 错误；既有 6 条涉及 mobile 三个 repository 的 SQL 类型及两个历史测试脚本，服务应用构建不受影响。
