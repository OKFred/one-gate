# 定时任务诊断与初始化优化计划变更

## 顺序

1. 在仓库外保存 TypeScript、定时测试基线，先提交设计和计划文件到工作区。
2. 修复服务端任务名/原因丢失，并复核另一个对话负责的客户端诊断。
3. 拆分 scheduled 服务注册与 HTTP 应用构造，补首次调用和重复调用回归。
4. 运行相关 Node/workerd 测试、构建、格式检查、TypeScript 前后对比；只读核对生产 Presence 和 D1。
5. 独立复核改动，记录实际落地、性能证据边界与仍未确认的问题。

## 外部协作和不涉及的变更

客户端仓库 `one-autojs6` 的 `report-error.ts`、调用处和相关测试由原客户端对话负责。本仓库记录安全化结果，不复制手机配置或标识。

无接口合同、菜单、权限、数据库 schema、数据保留期限、设备认证或发布配置变更。暂不增加 MQTT 转发、即时写重试、CPU 配额、自动发布。业务 Cron 吞掉单个可编辑作业失败等既有行为若超出本轮范围，记录后续项。
