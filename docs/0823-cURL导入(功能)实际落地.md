# cURL 导入功能实际落地

## 需求与范围

- 在 `/admin/maintenance/api-task` 增加 cURL 文本粘贴入口和一键导入能力。
- 使用 `dist/renrui.sh` 作为解析验证样例。
- 本次为独立前端增强，复用现有 `bulkAdd` 接口，不改后端接口、数据库表或 OpenAPI 类型。

## 实际改动

- 新增独立的“从 cURL 导入”按钮与弹窗，不影响原有 Swagger/OpenAPI 文档导入流程。
- 新增无第三方依赖的 cURL 解析器，提取 HTTP 方法、URL、headers、超时时间和内联 JSON body。
- 同时兼容 Bash 反斜杠和示例文件使用的脱字符多行续行格式。
- JSON body 转换为带 `examples` 的请求 Schema；表单、文件引用和多段 `-d` 会被明确拒绝，避免生成无法由现有执行器还原的任务。
- 新增中英文界面文案，并提示 Authorization、Cookie 等敏感请求头会持久化。

## 与计划对比

本次属于小范围页面增强，未单独创建设计和计划文档。实际落地与直接需求一致；额外增加了敏感信息提示、错误反馈和请求体能力边界说明。

## 验证与后续建议

- 改动前、改动后的管理端 TypeScript 检查均为 0 报错。
- `dist/renrui.sh` 解析验证通过：识别为 POST，请求地址拆分正确，保留 12 个请求头，并生成包含原始 JSON body 的 Schema 示例。
- 默认 GET、`--json`、Bash 多行续行、表单拒绝和未闭合引号等边界用例验证通过。
- ESLint、Prettier、`git diff --check` 和管理端生产构建通过；构建仅输出项目既有的 chunk 体积提示。
- 后续如需支持 multipart、文件上传或原始文本 body，应先扩展 API Task 执行模型，避免导入配置与真实请求行为不一致。
