## 一、需求背景与范围调整

### 本期范围

实现 **浏览器用户之间的实时音视频通话**（App-to-App），不接入真实电话网络（PSTN）。

典型场景：
- PC 管理员通过网页发起音视频会话，连接另一个浏览器用户或 Android 移动端（AutoJS6）
- 多方会议支持（视需求扩展）
- 可选：纯音频模式（关闭摄像头只开麦克风）

### 为何不用 Twilio

上一期方案（PSTN）依赖 Twilio，需购买号码、依赖第三方云媒体中转，成本与合规复杂度较高。

App-to-App 场景直接使用 **Cloudflare RealtimeKit**：

- 账号下已有该产品，Beta 期间**完全免费**
- 无需引入第三方 SDK 依赖
- 与现有 Cloudflare Workers 架构天然融合
- 提供 React / Web / Android / iOS / Flutter 全平台 SDK

## 二、技术选型

### 2.1 Cloudflare RealtimeKit 核心组件

```
浏览器 A ──WebRTC──┐
                   ├──► Cloudflare 无服务器 SFU ──► 媒体分发
浏览器 B ──WebRTC──┘       ▲
Android App ──WebRTC──┘    │
                    TURN 服务器（NAT 穿透，配合 SFU 免费）
                            ▲
                    Hono Workers 信令控制（签发 authToken）
```

| 组件 | 本项目使用方式 |
|------|--------------|
| **RealtimeKit API** | 后端调用创建 Meeting / 生成 authToken |
| **无服务器 SFU** | 媒体流转发（Cloudflare 托管，无需运维） |
| **TURN 服务器** | 配合 SFU 自动使用，免费 |
| **@cloudflare/realtimekit-web** | 前端 Web 组件（Vanilla JS/TS） |
| **@cloudflare/realtimekit-react** | 前端 React SDK（首选） |
| **@cloudflare/realtimekit-react-ui** | 开箱即用的 UI Kit（含拨号/会议界面） |

### 2.2 双运行时适配

| 操作 | Node.js | Cloudflare Workers |
|------|---------|--------------------|
| 创建/查询 Meeting | ✅（fetch CF API） | ✅（fetch CF API） |
| 生成 authToken | ✅（fetch CF API） | ✅（fetch CF API） |
| 前端 SDK | 纯浏览器，与运行时无关 | 同左 |

> **重要**：RealtimeKit 的所有信令逻辑由 Cloudflare API 完成，后端只需做**鉴权 + HTTP 中转**，无双运行时差异。这是相较于 Twilio JWT 签名方案的最大优势。

### 4.3 API 列表（`service.ts`）

所有接口返回结构严格遵守：
```typescript
{ ok: boolean; message: string; data: Record<string, unknown> }
```

#### ① `POST /api/v1/admin/voice/meeting`

**用途**：创建一个 RealtimeKit 会话（Meeting）。

- **权限**：需登录
- **异步原则**：立即创建内部 taskId 和 log，立即返回 meetingId
- **内部实现**：调用 `POST https://api.cloudflare.com/client/v4/accounts/{id}/realtime/kit/{appId}/meetings`

```
请求：{ title?: string }
响应：{ ok: true, message: "", data: { meetingId: string, taskId: string, status: "EXECUTING" } }
副作用：写入 admin_voice_session_log（status: 'active'）+ MQTT 通知
```

#### ② `POST /api/v1/admin/voice/join`

**用途**：为当前登录用户生成加入某个 Meeting 的 authToken。

- **权限**：需登录
- **内部实现**：调用 CF API 添加 Participant，返回其 `token`

```
请求：{ meetingId: string, displayName?: string }
响应：{ ok: true, message: "", data: { authToken: string, meetingId: string } }
```

#### ③ `POST /api/v1/admin/voice/meeting/end`

**用途**：标记会话结束（逻辑删除 / 状态变更）。

```
请求：{ meetingId: string }
响应：{ ok: true, message: "", data: {} }
副作用：更新 log status = 'ended' + endTimeUtc + MQTT 通知
```

#### ④ `POST /api/v1/admin/voice/meeting/list`

**用途**：分页查询会话日志。

```
请求：{ page: number, pageSize: number, status?: 'active' | 'ended' }
响应：{ ok: true, message: "", data: { list: VoiceSessionLog[], total: number } }
```

### 5.4 `useVoiceSession.ts` Hook 接口设计

```typescript
import type { RealtimeKitClient } from "@cloudflare/realtimekit-react";

interface UseVoiceSessionReturn {
  meeting: RealtimeKitClient | null;   // RealtimeKit 会话实例
  joining: boolean;                    // 是否正在加入中
  startCall: (opts?: { title?: string }) => Promise<void>;  // 发起新通话
  joinCall: (meetingId: string) => Promise<void>;           // 加入已有通话
  endCall: () => Promise<void>;        // 结束/离开通话
}

/**
 * 封装 RealtimeKit 会话生命周期
 * - startCall: 创建 Meeting → 加入（获取 authToken）→ initMeeting
 * - joinCall: 直接加入（获取 authToken）→ initMeeting
 * - endCall: 离开 + 更新后端状态
 * - 组件卸载时自动 leave 避免资源泄漏
 */
export function useVoiceSession(): UseVoiceSessionReturn;
```

**核心流程**：

```typescript
// startCall 内部实现
async function startCall(opts) {
  setJoining(true);
  try {
    // 1. 创建会话
    const createRes = await createMeetingFn({ title: opts?.title });
    const { meetingId } = createRes.data.data;

    // 2. 获取 authToken
    const joinRes = await joinMeetingFn({ meetingId });
    const { authToken } = joinRes.data.data;

    // 3. 初始化 RealtimeKit
    const [mtg, init] = useRealtimeKitClient();  // 或直接调用 SDK
    await init({ authToken });
    setMeeting(mtg);
  } catch {
  } finally {
    setJoining(false);
  }
}
```

## 六、MQTT 联动设计

通话发起/结束时，通过现有 MQTT 推送通知给移动端（one-autojs6）：

```typescript
// 发起通话时推送
mqttPublish({
  topic: `voice/invite/${targetUserId}`,
  payload: JSON.stringify({
    action: "incoming_call",
    meetingId,
    callerName: currentUser.name,
    joinUrl: `${baseUrl}/voice?meetingId=${meetingId}`,
  }),
  qos: 1,
});

// 结束通话时推送
mqttPublish({
  topic: `voice/status/${meetingId}`,
  payload: JSON.stringify({ action: "call_ended", meetingId }),
  qos: 1,
});
```

## 八、与 v1.0（PSTN）方案的主要差异

| 项目 | v1.0 PSTN（Twilio） | v2.0 App-to-App（CF RealtimeKit） |
|------|--------------------|---------------------------------|
| 能打真实手机号 | ✅ | ❌ |
| 费用（当前） | 按分钟计费 | **Beta 免费** |
| 后端复杂度 | 高（JWT 双运行时签名、TwiML 回调、Webhook 验签） | **低**（纯 HTTP 转发 CF API） |
| 前端依赖 | `@twilio/voice-sdk` | `@cloudflare/realtimekit-react` |
| 录制支持 | ✅（Twilio 云） | ✅（RealtimeKit R2，可选） |
| PSTN 后续扩展 | 原生支持 | 需额外接 Twilio/阿里云网关 |
| `driver.ts` | 需要（JWT 签名） | **不需要** |
| TwiML 回调接口 | 需要（2 个 Twilio Webhook） | **不需要** |
