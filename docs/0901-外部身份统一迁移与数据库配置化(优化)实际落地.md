# 外部身份统一迁移与数据库配置化实际落地

## 当前状态

状态：Hodor 代码、append-only migration 和本地验证已完成；远程 D1、数据库配置写入、PR 合并
与部署尚未执行。

Hodor 的交互式登录面现只保留账号密码和标准 OIDC Identity Center。GitHub、飞书不再由 Hodor
活动代码直连；历史 OAuth 表与 migration 原样保留，不迁移、不删除历史数据。

## 实际完成范围

### 数据库配置与 SSO 用例

- 新增无外键单例表 `system_sso_connection`，保存 issuer、Client ID、audience、允许租户、精确
  redirect URI、`draft | ready | disabled` 状态、乐观版本和最近测试信息。
- 增加 D1 `0010_sso_connection_configuration.sql`、Node migration、Drizzle model、SQL contract
  和 Schema Contract；既有 migration 没有改写或重排。
- SSO 运行时数据库优先；仅当表中没有配置时，才在一个发布观察周期内完整回退旧 `SSO_*`
  环境变量。数据库中的 `draft` 或 `disabled` 不会回退环境变量。
- `HODOR_AUTH_MASTER_KEY` 成为新的认证根密钥名称；兼容期保留
  `OAUTH_SENSITIVE_DATA_KEY` 回退，避免正在进行的 PKCE transaction 失效。
- 新增管理员且受 TOTP 保护的 `get/save/test/disable` 配置接口：
  - `save` 使用 `expectedVersion` 并回到 `draft`。
  - `test` 校验 HTTPS、OIDC discovery、issuer、JWKS 和 redirect URI 后原子切换为 `ready`。
  - `disable` 使用条件更新，版本冲突返回 409。
  - 缺少或不可用配置时只让 SSO 失败关闭，密码登录保持正常。

### Hodor 直连 Provider 下线

- auth service 不再导出 GitHub、飞书和微信 WIP API；旧 `/oauth/*` 不在 Hono 路由树或匿名白名单
  中，因此统一返回 JSON 404。
- 删除活动 OAuth application、provider adapter、state、cipher、repository 和 HTTP 实现；历史
  `system_user_oauth`、`system_oauth_state` Schema 与 migration 继续保留。
- 用户资料响应删除 `githubUsername`、`oauthBindings`，OpenAPI 导出和前端生成类型同步更新。
- 登录页只显示密码和 Identity Center；账号页只保留密码与 SSO 绑定/解绑；旧 OAuth callback 页面
  与辅助代码已删除。
- 现有 SSO Authorization Code + S256 PKCE、明确绑定、回调和后置 TOTP 流程保持兼容。

### 部署安全

- CI、Wrangler 和示例配置已移除 Hodor 直连 GitHub/飞书业务变量。
- bridge 发布周期继续上传五个 `SSO_*` 与旧根密钥，等数据库配置写入并验证一致后再删除。
- 新增部署 Secret 非空预检，并保证它发生在任何远程 D1 migration 前；预检只输出缺失变量名，
  不输出值。
- 契约测试精确比较 Wrangler required、Wrangler Action upload 和 Action env 三组 Worker Secret，
  防止再次发生 migration 已执行后才发现上传 Secret 缺失的问题。

## 已知历史约束

Wrangler migration `0000_legacy_schema_baseline.sql` 是为已由旧 `db:init` 建表的数据库设置 ledger
起点的 transition marker，并不是完整空库基线。因此从完全空白的隔离 D1 直接回放 `0000`–`0010`
会在历史 `0001_system_user_oauth_security.sql` 处因基础表不存在而失败；本轮没有违反规则去改写已
发布 migration。

本次目标环境是已有 Hodor D1，`0010` 已在同结构的本地初始化库上验证通过。若要支持新开发者从
空 D1 仅靠 Wrangler migrations 初始化，需要单独设计新的基线/压缩迁移切换方案，不能在本 PR
偷偷修改历史 migration。
