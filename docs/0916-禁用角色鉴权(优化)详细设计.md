# 禁用角色鉴权详细设计

## 背景与范围

从最新 `dev`（`f3aa95c9`）创建 `codex/disabled-role-authorization`，继续完善回收站依赖的公共鉴权边界。当前普通角色权限服务已有启用过滤；实际缺口是鉴权直接从管理 DTO 的全部角色绑定推导身份、数据范围查询包含禁用角色，以及旧权限缓存不核对当前角色状态。超级管理员权限快捷分支也在启用检查之前执行。

本轮仅修复 JWT 角色鉴权及相关测试。保留角色绑定管理信息、部门引用保护和 API Token 自身授权语义，不新增数据库字段、迁移、API、菜单或前端表单。

## 有效角色查询

在 admin 角色仓储提供 `getAuthorizationRoles(ids)`，按 ID 升序查询指定且启用的角色，返回 ID、数据范围、自定义部门和更新时间。通过现有 role utils → systemRegister → registry 类型推导接入公共鉴权，不新增公共包对业务仓储的直接依赖。

每个 JWT 请求在构造身份时读取该数据库快照；`roleIds` 和 `isSuperAdmin` 仅从有效角色计算。管理 DTO 的 `roleArr` 保留禁用绑定，方便查看、解绑和重新启用。已删除或不存在的角色不参与授权。角色 1 的管理端禁用/删除保护继续保留，数据库中异常禁用的角色 1 也不得触发鉴权快捷通道。

普通权限仓储使用单条查询连接角色表，并同时限制角色与权限为启用；服务不再借用最多 10000 条的管理列表过滤全站角色。超级管理员权限快捷查询必须确认角色 1 当前启用。数据范围工具查询本身增加启用条件，鉴权则直接合并本请求的有效角色快照，避免额外查询与多处状态解释。

## 权限缓存

继续保留全局权限版本机制，缓存包新增格式版本和角色指纹。指纹由稳定排序的角色 ID、更新时间、数据范围、自定义部门组成。命中需要格式版本、角色指纹和全局版本全部一致；旧格式默认失效。角色禁用、删除、绑定变更或范围变更使当前角色指纹变化，旧包即使随旧全局版本一起返回，也不能被新的身份快照接纳。

缓存回写绑定本请求捕获的角色快照与查询前读取的版本，不把旧权限标记成查询后才出现的新版本。KV 读取失败时回退数据库，不能把失败推断为版本 `1` 后写回。Worker 后台缓存写入使用 `waitUntil`；Node 等待其完成，保证错误被处理。缓存不是角色状态的最终判断依据。

角色更新的 UTC 毫秒时间在单条 SQL 中取 `max(当前时间, 原更新时间 + 1)`，避免同毫秒连续禁用和重新启用产生相同指纹。它仍是更新时间，不新增数据库版本列；测试包含固定时钟下的连续状态切换。

此改动保证读取到禁用状态后的新请求不再采用该角色；不追溯取消已经完成鉴权的在途业务操作。权限映射的跨节点即时撤销、全局 KV 版本的强一致性不在本轮承诺内。若以后需要对每次业务写入提供线性化撤销，应另行设计数据库授权版本或事务内授权。

## 回收站与管理语义

禁用角色不再赋予回收站读取、恢复等操作权限，也不再贡献 ALL/CUSTOM 数据范围。角色绑定及自定义部门引用仍保留；部门删除、清理和恢复原有的引用条件不放宽，禁用角色引用仍阻止部门删除。

## 验证与发布

先记录 server 根目录与 server 应用 TypeScript 基线。新增真实仓储/服务、JWT 中间件与缓存集成测试，在 Node 内存库和本地 Worker D1 中执行：启用/禁用、ALL/CUSTOM 混合范围、无角色、异常角色 1、管理 DTO、旧格式与热缓存、禁用后再次启用、旧请求晚写回、缓存异常及部门禁用引用保护。

格式化与 TypeScript 前后对比后进行复盘；发现问题时按仓库规范先暂存再修改，最多五轮。执行相关测试、完整 Node 回归和构建，最后 `git diff --check`。通过 PR CI 后合入 dev，跟踪现有自动发布并核对版本与健康状态；线上验收只读，不通过停用真实角色试验权限撤销。分别记录本地代码验证、本轮无需迁移、CI 和上线验收。
