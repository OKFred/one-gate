## 实现与计划比对

- 按计划新增设备运行快照表、严格协议解析、带设备启用状态与报告 Token hash 的单条 CAS 存储，以及 state、cancel、report/task-state 三个 POST 接口。
- 队列来自手机真实快照，保留 STARTING、RUNNING、QUEUED；不修改历史 PENDING 的含义。60 秒接收新鲜度、session/revision 顺序和设备时间检查共同阻止旧快照伪装在线。
- 终止复用现有 MQTT 发布，新增控制路径强制 TLS 和证书校验，QoS 1、retain=false，30 秒指令窗口。仅允许同设备、同 scriptId 的本站协议 v2 活动任务；成功响应只表示请求已发送，最终结果仍由原任务回调决定。
- 前端区分未知、空队列、过期、读取失败和请求结果未知。自动刷新不会重复终止；明确手动刷新取得新鲜且仍可终止的任务后，需再次确认才能重发。设备、页签和身份变化隔离旧请求。
- 为本次原生 D1 回调回归额外修复了既有完成写入的假失败：由依赖 rowsAffected 改为条件 UPDATE RETURNING。任务身份与活动状态条件保留，重复或晚到终态不覆盖已有终态。
- 隔离浏览器验收发现抽屉关闭按钮被 AppBar 遮挡，在当前抽屉补用主题 modal 层级；表格状态入口补用已有翻译的无障碍名称。
- OpenAPI 类型由导出文件生成。没有新增依赖、数据库默认值、一级页面，PostgreSQL mobile 路由仍未开放。

## 部署前置条件与未验收边界

1. 本轮提交、推送及发布已获授权；完成秘密扫描和既有 PR/发布流程，保留当前 D1 数据和资源绑定。
2. Node 在维护窗口暂停相关写入，针对现有 SQLite 文件运行 `pnpm run db:migrate:mobile-task-runtime:node --database=<绝对文件路径>`。D1 使用新增编号迁移并运行结构契约；不通过 db:init 重置旧库。
3. 配套手机版本为对方本轮未提交的 2.1.30。必须配置 http 或 dual 报告模式、原 HTTPS API base URL 与设备 Token；仅 MQTT 模式不能为 Worker 提供本轮任务快照。
4. Broker 需要审核该设备精确 task-control 订阅和 task-state 发布权限，并提供可验证的 WSS/MQTTS。此次没有擅自扩 ACL、改证书或回退明文。
5. 使用合成无副作用任务验收实际 MQTT、HTTP、手机 STARTING/排队/运行终止、重连及回调 outbox。没有操作真实 TikTok 发布，也没有验证物理手机停止和外部副作用撤销。

Presence Will 仅可表示离线或会话丢失，不能代写 FAILURE/CANCELLED。本轮没有 Worker 的 broker Will webhook，页面依赖 60 秒快照过期；也未新增已终态任务的晚到结果证据存储。设备时间回退会拒绝旧快照，需修正时钟后重新上报；后台已 TIMEOUT 的任务不能通过本站按钮终止。
