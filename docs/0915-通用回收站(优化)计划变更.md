# 通用回收站计划变更

## 预计文件

- `server/packages/core/src/db/`：增加回收站适配器类型、注册表和测试，复用已有软删除期限及清理合同。
- `server/packages/admin/src/maintenance/recycle-bin/`：资源目录合同、通用接口分发、权限和白名单测试；移除部门直接依赖。
- `server/packages/admin/src/system/department/`：新增业务适配器及公开 facade 接入，保持原有数据库规则。
- `server/apps/server/src/`：统一资源组合注册，交互接口和到期清理复用；Node/Worker 调度入口保持每分钟执行。
- `platform/apps/admin/src/pages/recycle-bin/index.tsx`：资源目录、动态选择、能力驱动及异步状态隔离。
- `platform/apps/admin/src/locales/{zh-CN,en-US}/maintenance.ts`：业务无关页面文案。
- `platform/packages/ui/src/api/admin/maintenance/recycle-bin.ts`、`types/openapi.d.ts`：新增资源目录封装并从后端生成类型。
- `platform/e2e/`：更新隔离回收站 fixtures 和交互测试。
- `docs/0915-通用回收站(优化)实际落地.md`：记录实际差异、验证结果、复盘次数与后续接入说明。

## 顺序

1. 读取规范、刷新 dev、创建分支、记录 TypeScript 基线，先完成本设计与计划。
2. 并行完成 core/后端适配器和管理页面；应用入口完成注册与清理组合。
3. 生成 OpenAPI，格式修复、TypeScript 对比和测试构建。
4. 复盘权限、引用与删除版本、资源切换、依赖方向；必要时按规范暂存后修正。
5. 输出实际落地记录并完成差异检查。

## 影响

现有部门请求继续兼容，保留期限、存储字段、历史归档和删除语义不变。新增的资源目录通过现有回收站读取权限保护，无新权限和菜单节点。其他业务可通过实现并显式注册适配器接入，不需要改动通用接口和页面。

没有新增 DDL 或迁移，也不调用全量数据库初始化。仅在测试中接入第二种资源，不在生产注册虚构业务。
