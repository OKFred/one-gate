# 设备注册与上报 DDD 垂直切片详细设计

## 1. 背景

`server/packages/admin/src/mobile/device/service.ts` 当前接近千行，同时承担 HTTP Schema 与适配、管理员 CRUD、设备令牌、在线判定、Presence/Info/Event 上报、敏感信息加解密、自定义元数据、事件查询以及定时维护。MQTT Listener、Worker Scheduler 和 async-task 基础设施还直接依赖该 `service.ts`、`repository.ts`、`crypto.ts` 或 `metadata.ts`，使设备领域的规则难以独立测试，也让 HTTP 边界成为跨模块公共入口。

设备任务中心已经建立 domain/application/infrastructure/interfaces 分层，本轮将同一依赖方向复制到设备注册与上报中心，作为第二个可复用的 DDD 垂直切片。

## 2. 目标与非目标

### 2.1 目标

- 将设备注册、上报、事件与维护用例拆为四层，并由稳定 facade 对外提供能力。
- 保持数据库表、HTTP 路径、方法、Schema、权限、MQTT v2 载荷、设备令牌与加密上下文不变。
- 将在线窗口、事件时间窗、JSON 大小、能力、标识符、元数据和事件摘要规则下沉为纯领域规则。
- 让 Application 只依赖 Repository、Crypto、Clock 与 Token 端口，不依赖 Hono、`BusinessError`、Drizzle PO 或全局数据库实例。
- 让 MQTT Listener、Worker Scheduler 和 async-task 基础设施只依赖设备 facade。
- 使用 Fake Ports 覆盖关键用例，补足当前设备模块没有正式 Vitest 的缺口。

### 2.2 非目标

- 不修改 `admin_mobile_device`、`admin_mobile_device_event` 表或 D1 migration。
- 不新增设备状态、上报字段、事件类型、接口、权限或前端功能。
- 不修改 AutoJS6/one-autojs6 协议与实现。
- 不改变 150 秒在线窗口、30 天事件保留、5 分钟未来容差或 32 KiB JSON 限制。
- 不引入 Outbox、事件溯源、设备分组、远程注销或令牌自动轮换。

## 3. 分层设计

### 3.1 Domain

`domain` 只包含纯 TypeScript 规则与值对象：

- 设备是否有效在线及 Presence 状态转换。
- 能力列表、IMEI/Serial 一致性和上报 JSON 大小限制。
- 设备事件 ID、时间窗、battery/network/sms/notification 摘要与快照规则。
- reportedExtra、自定义元数据、敏感字段拆分与掩码规则。
- 领域规则违反统一抛出不依赖框架的 `DeviceRuleViolation`。为保持现有 HTTP 兼容，原先由 `service.ts` 主动校验的设备协议规则在 Application 映射为 `DeviceApplicationError`；原先由元数据工具直接抛出的结构错误继续透传为基础异常，本轮不改变其 HTTP 状态语义。

Domain 不读取时间、环境变量、数据库或加密密钥；当前时间由 Application 传入。

### 3.2 Application

`application/device-center.ts` 编排以下用例：

- 管理员设备列表、新增、更新、详情、删除。
- 更新自定义元数据、查看敏感数据、重置上报令牌。
- 验证设备令牌，接收 Presence、Info 与 Event。
- 查询事件、标记超时设备离线、清理过期事件。
- 为任务中心查询最小设备目标，为 MQTT 日志生成不可逆标签。

Application 定义自己的 Actor、DeviceRecord、EventRecord、输入和输出类型；领域异常转换为 `DeviceApplicationError`。它只依赖以下端口：

- `DeviceRepositoryPort`
- `DeviceCryptoPort`
- `ClockPort`

### 3.3 Infrastructure

`infrastructure` 提供：

- Drizzle Repository：负责 Drizzle PO 与 Application Record 之间的适配。
- WebCrypto/环境密钥适配器：复用现有 AES-GCM、PBKDF2、令牌哈希和随机令牌语义。
- 默认依赖装配：创建生产 `DeviceCenter` 单例。

基础设施可以依赖根 `model.ts`、`@hodor/core/db` 与环境配置，但不能被 Domain/Application 反向引用。

### 3.4 Interfaces

`interfaces/http` 负责：

- 从 Hono Context 读取 `x-device-token`。
- 将 `DeviceApplicationError` 映射为现有 `BusinessError(VALIDATION_FAILED)`。
- 将 HTTP JSON Schema 输入适配为 Application 输入。

根 `service.ts` 继续默认导出纯 API 对象，只保留 Schema 引用、adapter、权限和 facade 调用。

## 4. 稳定 facade 与依赖迁移

新增 `mobile/device/facade.ts` 作为唯一跨模块入口，提供：

- `verifyDeviceReportToken`
- `processDevicePresence`
- `processDeviceInfo`
- `processDeviceEvent`
- `markTimedOutDevicesOffline`
- `cleanupExpiredDeviceEvents`
- `findDeviceTaskTarget`
- `getDeviceLogLabel`
- 管理端与 HTTP 上报所需用例

调用方迁移如下：

- `mqtt/listener.ts`：由 `device/service.ts`、`crypto.ts`、`metadata.ts` 改为 facade；MQTT 载荷解析仍保留在 Listener 边界。
- `apps/server/src/worker.ts`：由 `device/service.ts` 改为 facade。
- `async-task/infrastructure/container.ts`：不再直接注入 `mobileDeviceRepo`，改用 facade 的最小任务目标查询适配。

## 5. 兼容性约束

根 API 对象必须仍只包含：

- `list`
- `add`
- `update`
- `get`
- `delete`
- `updateMetadata`
- `eventList`
- `reveal`
- `resetToken`
- `reportPresence`
- `reportInfo`
- `reportEvent`

所有接口继续使用 POST，路径、权限、请求/响应 Schema 不变。设备令牌仍从 `x-device-token` 读取；敏感数据仍使用相同 AAD；重复事件仍按 `(clientId, eventId)` 幂等；在线状态继续按服务端接收时间判定，不信任设备时间更新心跳。

## 6. 测试设计

### 6.1 Domain 单元测试

- 在线窗口边界与 Presence 状态转换。
- 能力、IMEI、Serial、JSON 大小和 reportedExtra 规则。
- battery/network/sms/notification 摘要与敏感标记。
- eventId、30 天保留窗口与 5 分钟未来容差。
- 自定义元数据数量、键名、值类型、敏感拆分与掩码。

### 6.2 Application Fake Ports 测试

- 新增成功与 clientId 重复。
- 更新时 clientId 不可变、设备不存在。
- Presence ONLINE/OFFLINE 快照和令牌校验。
- Info 标识符加密、掩码、能力规范化。
- Event 首次插入、重复事件、快照更新和敏感载荷加密。
- 元数据占位符保留旧敏感值、Reveal 解密、重置令牌。
- 在线超时、事件清理、任务目标查询和日志标签。

### 6.3 兼容性测试

- HTTP API 对象键、路径、POST 方法与权限不变。
- 修改前后 Windows 服务端 TypeScript 诊断对比。
- Windows 定向 Vitest、服务端构建、ESLint/Prettier。
- `git diff --check`、LF/UTF-8/BOM、无新增 `any/as any`。

## 7. 风险与控制

- 设备模块包含敏感数据：测试只使用哨兵假数据，不输出真实令牌、密文或标识符。
- 纯重构容易产生边缘语义漂移：先固定领域规则和 HTTP API 形状，再迁移调用方。
- Windows/WSL 依赖不兼容：所有 Node、pnpm、TypeScript、Vitest 和构建命令只在 Windows 环境执行；WSL 仅用于文件读取、补丁和 Git。
