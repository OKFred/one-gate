# 通用回收站实际落地

## 结果与范围

2026-09-15，基于最新 dev `919e0fa6`，在 `codex/recycle-bin-registry` 完成代码改造。回收站页面、接口分发与公共注册表已解除部门依赖；应用组合入口仅注册部门作为首个真实资源。

本次代码尚未合入 dev、提交发布或部署。线上仍是之前发布的部门试点版本；本报告的 UI 验证使用隔离 mock，不代表新版线上验收。

## 实际实现

| 层次       | 实现                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 公共合同   | `server/packages/core/src/db/recycle-bin.ts` 提供资源适配器、记录摘要、数字或字符串 ID、显式注册表；无业务包导入。               |
| 统一接口   | `server/packages/admin/src/maintenance/recycle-bin/` 根据注册表分发；新增 POST `/resources`，保留原 list、restore、purge 路由。  |
| 业务适配器 | `server/packages/admin/src/system/department/recycle-bin.ts` 封装现有部门服务，facade 暴露接入点；原 SQL 及数据库模型未改。      |
| 应用组合   | `server/apps/server/src/recycle-bin-resources.ts` 显式注册部门；HTTP 与冷启动定时调度均加载该模块。                              |
| 清理调度   | 每轮从相同注册表派生清理适配器；保留历史部门归档独立适配器，每类 100 条上限、失败隔离及监控日志不变。                            |
| 页面       | 从服务端目录获取类型、翻译键和操作能力；支持选择资源、搜索分页、空目录与失败重试；请求和确认使用记录自己的资源键、ID、删除版本。 |

资源目录只显示同时满足回收站读取权限和业务读取权限的类型。列表、恢复、清除均在服务端重新验证入口权限及业务权限；提前清除额外验证当前登录身份 `isSuperAdmin`。摘要显式选择公共字段，业务适配器返回的附加字段不会进入响应。

页面不再依赖部门权限或固定 `department` 请求值。切换类型会清除搜索、页码、记录和弹窗选择，旧请求响应不能覆盖新类型。记录键包含资源类型与原始 ID 类型。保留期状态按期限展示，缺少恢复权限不会被误标为过期。

## 与计划的差异

- 实现范围与计划一致，未迁移其他业务表，未新增集中快照表、数据库字段或到期时间字段。
- 额外明确 ID 合同：安全正整数或最多 256 字符的非空字符串；部门适配器仍仅接受安全正整数。
- 复核时将逻辑资源键正则改为严格结束断言，拒绝末尾换行。注册冲突拒绝替换；重复注册同一个适配器对象保持幂等。
- 新增真实 HTTP 封装层测试，覆盖目录权限、请求 Schema、逻辑资源白名单、字符串 ID 与普通账号清除限制。
- 新增 `HTTP 200 + ok:false` 重名错误 UI 用例，明确检查提示可见、弹窗和记录保留。
- Node/Worker 原有分钟调度入口本身无需修改，通过应用组合接入即可。现有菜单、BusinessKey、权限节点仍适用；资源目录复用回收站 read 权限，因此无需全量初始化数据库。

## 后续业务如何接入

1. 业务模块自行完成原表软删除字段、迁移、普通查询隐藏和引用保护。
2. 实现 `RecycleBinResourceAdapter`：`resourceType`、`labelKey`、`can`、`list`、`restore`、`purge`、`purgeExpired`。交互方法获得当前 `UserObj`，业务模块负责自己的数据范围。
3. 通过业务公开 facade 导出，在 `server/apps/server/src/recycle-bin-resources.ts` 增加一处显式注册，并提供资源名称的中英文翻译。
4. 查询、恢复、清除和到期清理随注册一起接入，无须修改通用接口、页面或调度代码。

部门是全局组织配置，当前适配器沿用原部门管理的全局可见范围。未来涉及租户、个人或部门数据范围的资源，必须在适配器查询与条件写入中执行对应限制；通用层传入用户上下文，不自动生成业务过滤条件。

恢复时，业务条件 SQL 必须同时检查实际删除状态、预期删除时间和未满 30 天，并保留原记录身份及业务约束。彻底清除前重新检查业务引用；自动清理也必须按状态、期限和引用条件删除。目录和页面显示的能力不代替这些最终检查。
