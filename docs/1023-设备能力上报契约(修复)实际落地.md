# 设备能力上报契约修复实际落地

日期：2026-10-23。基线：`87fad15f`。分支：`codex/hodor-maintenance-diagnostics`。

## 实际改动

设备领域增加 `DEVICE_REPORTED_OPERATIONS`，明确镜像客户端当前 15 项受控能力。`validateCapabilities` 从类别正则改为精确集合校验，使亮度 get/set、UI target-at、telephony get、alert find 五项实际能力可以正常报告，同时拒绝清单之外的格式相似名称。

继续保留协议版本、boolean enabled、`arbitraryShell=false`、最多 50 项和输入复制约束。没有接口形状、权限、数据库或部署绑定变更。

能力报告只写设备元数据。DO 的独立 10 项执行清单和认证链没有修改；五项新增可报告名称仍不能下发执行，也不会创建执行审计或转发给设备。前端设备详情展示和运维通道许可仍分别使用原有机制。

## 与计划对比

领域实现及 HTTP 报告验证按计划完成。额外在现有 `mobile-ops-session.workers.spec.ts` 增加六个执行拒绝用例，保护报告清单与执行许可的边界。没有扩大远程控制功能。

两份详细设计和计划在源码变更前完成。完成一轮完整独立复核，无阻断项；DO 测试另经独立交叉核对。无需进入后续修正循环。
