# 私人日历 ICS 订阅详细设计

## 目标

为现有私人日历增加 Apple Calendar 可读取的私有只读 ICS 订阅。新增、编辑、取消仍由 One Gate 完成；客户端按自己的刷新策略同步。导出事件提醒，站内“知道了”不移除 Apple 的提醒。首期不做 CalDAV 双向编辑，不把健康记录接入订阅。

## 身份与接口

订阅管理继续使用本人登录与 TOTP，API Token 和超级管理员跨用户操作均拒绝。新增 POST `/api/v1/personal/calendar/subscription/status`、`rotate`、`revoke`。status 返回配置状态、是否启用、当前版本和更新时间；rotate/revoke 携带 expectedVersion，允许首次 null，仅条件写入成功后报告成功，禁止自动重试写操作。

每人一个订阅记录，保存 ownerUserId、tokenHash（nullable/unique）、version、createTimeUtc、updateTimeUtc，无数据库默认值；停用将摘要清空并递增版本。随机 256-bit 只读 secret 明文仅生成时返回，数据库只存 SHA-256。重新生成使旧链接立即失效，状态查询不回显旧链接。界面可复制 HTTPS 地址或通过 webcal 唤起系统客户端，退出、换账号、离页清除明文。链接不进入公开报告、URL状态或浏览器持久存储。

采用独立协议资源 `GET/HEAD /calendar-subscription.ics?token=…`，放在 `/api/v1` 之外，遵循已有 health/version/doc 独立 GET 协议路由模式；现有业务 POST、鉴权路径分类和 TOTP 不放宽。不把 feed 塞进使用前缀匹配的既有 bypass 列表。只接受精确路径、GET/HEAD、单个规范 token 参数；所有相邻路径和其他方法拒绝。摘要查找后同时验证 owner 用户仍存在且启用，只读取该 owner 的事件。

配置 `CALENDAR_SUBSCRIPTION_ORIGIN` 为固定 HTTPS origin，不从 Host/Forwarded 请求头生成链接，配置缺失时禁用管理创建和 feed。首次上线需要对专用订阅路径适配 Cloudflare Access，由订阅 secret 进行只读验证；其余站点/API保持原登录保护。外部访问规则与真实新凭据的最终启用单独核对，不擅自扩大整个站点匿名访问。

## iCalendar 合同

RFC5545：CRLF、UTF-8 按 75 octets 折行且不拆字符、TEXT 转义反斜杠/换行/逗号/分号。稳定 UID 基于原 UUID，SEQUENCE 使用事件编辑版本，DTSTAMP/LAST-MODIFIED 使用更新时间，DTSTART/可选 DTEND 使用 UTC 秒格式。没有结束时间不捏造一小时。标题、说明、http(s) 事件 URL 和明确设置的 DISPLAY VALARM；不给事件附带管理或订阅 secret 链接。取消事件在完整订阅快照中移除。

不复用现有 93 天/500 条分页列表。独立读取全部活动事件，上限 1000 条，超过或序列化超出 2 MiB 明确失败，不发布残缺日历，避免客户端误认为记录已删除。异常日期或非法数据明确失败，不静默丢记录。响应 private/no-store、禁止共享 CDN 缓存；鉴权在任何 ETag/304 之前。本期可不提供 304，避免撤销及用户停用后缓存仍返回成功。

无效、撤销、停用 owner 均返回相同无数据拒绝，不透露账号身份。不给 URL参数、token、ICS 或用户完整日程写应用日志。现有日志只记路由模板；Cloudflare 平台 tail 可能含完整 request.url，不能宣称 query secret 天然不会入日志，发布记录必须说明日志排除/脱敏与可撤销链接边界。

## 存储、验证与交付

SQLite/D1/PG 同构，D1 预计 0021、PG 0004（生成前复核），仅新增迁移，Node 增量事务迁移带 marker/checksum/回滚；不改历史、不 reset、不 db:init。公共协议通过 personal 导出的挂载函数接入主 app，不跨业务包私有 service。

验证 owner 隔离、关闭账号、token 猜测/重置/撤销、并发 CAS、重复 query/非法路径/方法、UTF-8/CRLF/注入、UID/SEQUENCE/取消同步、VALARM、无结束时间、1001 条与超大响应、三数据库迁移与旧数据保留。增加管理 UI 和浏览器会话隔离测试，更新 OpenAPI 中管理接口。记录应用 TS 前后差异、格式/lint、相关回归与构建、复核及实际落地；协议/真实 feed 拉取与真实 Apple 设备验收分开，本机 Windows 不冒充 Apple 设备验收。

依据：[Apple 订阅说明](https://support.apple.com/en-ie/102301)、[RFC5545](https://www.rfc-editor.org/rfc/rfc5545.html)、[Cloudflare Access 路径](https://developers.cloudflare.com/cloudflare-one/access-controls/policies/app-paths/)。
