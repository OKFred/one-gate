# 健康档案与时间线实际落地

## 页面文字精简

按后续用户反馈去掉内容区“健康档案”和“记录就诊、检查与用药”两行，网格自然上移，不保留空白占位；面包屑回退复用原有“健康与医疗”导航词条，中英文孤立标题和副标题词条同时清理。保留身体部位参考、档案与时间线交互。此次为小范围展示调整，进行两轮范围复核及定向格式、类型与构建检查，无新增数据库、API 或权限变更。

## 本轮状态

用户已选展示方案 1，并追加时间线。本轮在既有健康页完成档案布局与交互改造，保留之前完成的 owner 安全修复。记录数据、表结构、原接口合同及 PG 能力边界未改。本记录固化上线前的实现与验收，后续提交、部署版本和生产验收以独立发布回执为准。

## 界面与交互

- 保留左侧七部位参考与右侧档案列表。按就诊日期倒序、按月分组，同月记录通过 MUI Timeline 连接，日期/类别/标题/就诊机构/操作保持对齐；部位入口只打开中性参考说明，不作为没有模型支持的筛选。
- 移除原大面积动画人体图、无来源的生命体征、健康结论及养生建议。没有真实数据的指标不再伪装为当前用户的实时健康状态。
- 接入现有服务端关键词、五类别、页码/条数与总数。关键词实际搜索标题、医院、医生和诊断；没有新增日期范围参数，也没有在当前页做伪全量检索。
- 新增完整记录详情与表单，支持就诊日期、机构、医生、诊断、处方、报告、费用和备注。未改就诊日期时保留原 UTC 毫秒；金额不接受非有限值，新增留空由既有服务初始化 0，编辑留空保持旧金额，明确输入 0 可归零。报告只打开 HTTP(S)，使用 noopener/noreferrer；不新增文件上传或服务端抓取。
- 仅有 read 时请求/显示列表，新增、编辑、删除分别检查原权限。删除沿用原硬删除机制，明确提示不可撤销；不顺带增加健康软删除或专用恢复接口。
- 查询绑定会话、AbortController 和代际，切换筛选时隐藏旧查询数据；写入成功失效旧查询。明确 HTTP/业务成功后才关闭表单，响应丢失保留“结果未知”并锁定当前重提；无自动写重试。
- 成功结论与列表刷新错误分开；新写操作开始时清除上次成功提示，避免混淆未知结果。退出或换账号清空列表、详情、表单和删除窗；不持久化医疗正文，不新增正文日志。
- 窄屏折叠部位导航、堆叠档案，搜索提交收进输入框并支持 Enter；沿用语义色与现有字体，兼容明暗主题。
- 修复 federation 实际加载 AppContent 却漏过本地语言初始化的问题：App/AppContent 共同引入 register，补齐 en-US/zh-CN，当前缓存覆盖本地默认值，保持已加载及随后返回的数据库热修复优先。

## 已落地的必要修复

原列表对创建人条件可选，更新/删除仅按 id。现在列表、详情查询及更新/删除持久层均要求有效 owner；服务只接受有效 human principal 的正整数 userId，拒绝 API Token、非法身份和旧字段回退。超级管理员不能越过归属条件。

更新/删除使用最终 SQL 的 owner+id 条件，外部与不存在记录统一原有 404，避免泄露记录归属。审计人字段由服务端初始化与更新，客户端字段不再通过展开覆盖。

只用合成记录验证：Node 10/10、原生 Worker/D1 10/10，包含本人/他人、非法身份、审计字段和最终条件。两轮专项复核及独立只读复核均无新发现；格式、lint、diff 检查通过，server 应用 TS 基线与最终均为 0。

## 与计划的差异

三张方案依次为档案列表、时间线、主从阅读布局，收到用户选择后才开始健康 UI 实施。只采用已支持的七个部位，未照搬生成图中额外的部位及不存在的部位关联筛选；完整保留住院类别。参考只使用空状态或合成记录，未把真实医疗资料发往生成工具。

首轮使用 core Stepper，但真实截图显示连线不足；视觉复核后改用仓库已有版本 MUI Lab，仅 personal package 增加同版本依赖、lock 增加该 importer 三行，无 snapshot 或其他依赖版本漂移。另按截图修正重复搜索图标、主要档案文字过小；按交互验收清理旧成功提示。

## 验证与边界

代码采用五轮复核，包括独立只读逻辑检查；第五轮最终截图发现部位 Drawer 被固定顶栏遮盖，已仅将该 Drawer 的层级改为主题 modal，并在桌面和 320px 验证标题/关闭可见、指针关闭后 dialog/menu 数量均为 0。Personal 应用 TS 本轮改前 0、改后 0；admin TS 0，Personal 生产构建、隔离 admin/personal 构建、定向 Prettier/ESLint 与 diff 检查通过。既有构建的大 chunk 提示保留，没有把它记成编译错误。

浏览器使用既有 Chrome，经原生 UI 登录两个纯合成账号，全部 HTTP 指向仅绑定 loopback 的内存夹具，CSP 阻止外网请求，无真实凭据、数据库或医疗资料。未运行 Playwright CLI，也未用构建成功替代浏览器验收。

已验证：桌面档案/时间线、320px 明暗主题、768px 平板无页面横向溢出；窄屏键盘切换分类、打开表单与初始焦点；搜索/组合空状态/清除；详情与安全外链；编辑日期毫秒保留、原生日期新增；保存成功但刷新失败分离；响应已提交但丢失后的未知提示与当前表单禁重提；HTTP200 业务拒绝仅提示一次；5 秒延迟旧查询不覆盖新查询；23 条记录的三页及总数缩减自动回有效页；删除确认/取消不发删除请求；新写操作不继承旧成功；只读权限仅查看；退出及切换账号后没有旧记录残留。DB 同名热修复先于远端加载的实际顺序与可见标题已验证。

最终同图比对及浏览器错误核对结果见项目根 `design-qa.md`。中英文 61 个词条集合一致，46 个字面量及动态类别/部位键覆盖检查通过；中文实屏通过，英文实屏未执行。Windows 浏览器隔离验收不等同生产 D1 或真实医疗档案验收，未实际删除任何用户数据；本轮浏览器只验删除确认与取消，最终 SQL 隔离由 Node/Worker 合同验证。

本地旧预览停止操作被自动审批拒绝，保留原进程；替代端口的新构建与 check 成功，但启动新进程同样被拒绝，返回理由均只有“blocked by policy”，未重试终止或换方式启动。现有 5198 健康页可用，继续留作预览；该旧版合成服务缺语言列表 mock，英文实屏复查因此保留为未执行，新版 mock 与 5199 构建已备好但没有 listener。没有操作线上资源。后续上线仍沿仓库既有发布与验收流程，私人日历订阅的部署配置见其独立落地文档。当前无新增未修复的应用 TypeScript 诊断；现有全局路由警告与可选视觉细节不在本轮扩修。
