# 设备主动上报与可扩展档案（功能）实际落地

## 1. 落地结论

设备主动上报已经整合到现有 `#/admin/mobile/device`，没有新增一级页面。实现同时支持：

- Node 通过 MQTT 接收 Presence、设备静态信息和设备事件。
- Worker 通过带独立设备令牌的 HTTPS 接收相同协议载荷。
- Node 定时器与 Worker Scheduled 共用 150 秒离线判定和 30 天事件清理服务。
- 管理端列表 30 秒静默刷新；设备状态抽屉的事件页 10 秒刷新，且仅在页面可见时执行。
- `DeviceAppDrawer` 保持只负责应用安装下发，没有恢复 App 信息获取。

## 2. 手机端

### 2.1 上报生命周期

- Presence 每 60 秒上报一次，MQTT retained Will 用于异常离线。
- 静态设备信息以进程级 Promise 只采集一次；MQTT 重连只复用并重发缓存。
- 电量、网络、短信、通知由可配置 AutoJS6 Observer 监听，仅变化或产生事件时写入事件文件。
- 每条事件使用 UUID `eventId`；`both` 模式下 MQTT 与 HTTP 复用同一载荷和 `eventId`。
- HTTP 上报设置请求超时，并使用 `X-Device-Token`，失败不会泄露正文或令牌。

### 2.2 静态信息与降级

采集厂商、品牌、型号、Android 版本/SDK、AutoJS6 版本、客户端版本、可信脚本、Root 能力、最多四个卡槽的 IMEI 和硬件序列号。IMEI 去空、去重；系统拒绝读取时记录 `unavailable`，客户端继续运行。

短信、通知监听默认启用，也可在 `autojs6-config.json` 中关闭或配置通知包名白名单/黑名单。Observer 与客户端日志均不记录号码、正文、通知内容或真实设备标识。

## 3. 服务端与数据

### 3.1 数据模型

`admin_mobile_device` 增加在线快照、客户端/系统版本、电量、网络、标识脱敏值/密文、可信能力、`reportedExtra`、`customMetadata` 和设备令牌摘要。

新增 `admin_mobile_device_event`：

- `(client_id, event_id)` 唯一，保证 MQTT/HTTP 双通道幂等。
- 保存事件类型、客户端事件时间、非敏感摘要、敏感正文密文和服务端创建时间。
- 以服务端创建时间执行 30 天清理，避免伪造客户端时间绕过保留策略。

迁移文件：`server/packages/core/src/db/migrations/20260810_11_mobile_device_reporting.sql`。

### 3.2 安全边界

- `MOBILE_SENSITIVE_DATA_KEY` 必须是 Base64 编码的 32 字节密钥。
- IMEI、序列号、短信/通知正文、敏感自定义字段使用 AES-256-GCM；12 字节随机 IV，并绑定字段级 AAD。
- 缺少或错误密钥时拒绝处理敏感数据，不会回退到明文。
- 列表和详情只返回脱敏标识及敏感占位符；reveal API 需要 `admin.mobile.device.view`。
- 每台设备的上报令牌为 32 字节随机值，数据库仅保存 SHA-256；明文只在生成/重置时返回一次，重置会立即使旧令牌失效。
- HTTP 拒绝未知设备、禁用设备、缺失/错误/已重置令牌；MQTT 同样拒绝未知或禁用设备，身份由 MQTT Broker 认证边界承担。
- 事件、能力和扩展载荷均有大小及结构限制；日志使用不可逆短标签，不记录真实设备标识或事件正文。

### 3.3 扩展元数据

- `reportedExtra` 只允许可信设备上报。
- `customMetadata` 只允许管理员编辑，每个值可标记 `sensitive`。
- 每个区域最多 50 个根键，总 JSON 不超过 32 KiB，键名需匹配稳定命名规则。
- 值只允许字符串、有限数字、布尔值和最多三层的简单数组。
- 正式字段名和 IMEI、序列号、令牌、手机号等敏感键不能进入普通扩展 JSON。
- 敏感语义的管理员字段必须标记敏感后加密保存。

## 4. 管理端

设备列表新增在线状态、型号/Android、客户端版本、电量、网络、最后心跳及在线筛选。轮询不改变当前页、分页大小和筛选条件。

“设备状态”抽屉包含：

- 概览：在线状态、硬件/客户端版本、脱敏标识、可信脚本能力、reveal、令牌生成/重置。
- 扩展信息：只读设备上报字段、管理员键值编辑器、敏感标记与敏感 reveal。
- 事件：最近事件、事件类型/起止时间筛选、敏感正文 reveal。

令牌重置前有二次确认，关闭明文对话框后不能再次查看旧明文。

## 5. Node 与 Worker

Node MQTT 监听与 Worker HTTP API 调用相同业务函数。Node 每 60 秒执行超时扫描、每天执行事件清理；Worker `scheduled` handler 执行同一组维护操作，Cron 配置使用 UTC。

实现依据：

- [Cloudflare Workers Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/)
- [Cloudflare Workers Scheduled Handler](https://developers.cloudflare.com/workers/runtime-apis/handlers/scheduled/)
- [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)

## 7. 部署注意事项

1. 在 Node `.dev.vars`、生产环境和 Worker Secret 中分别配置同一用途的 `MOBILE_SENSITIVE_DATA_KEY`，不要提交明文密钥。
2. 执行数据库迁移后再发布服务端。
3. Worker 配置 Cron 后，确认触发时间按 UTC 解释。
4. 为每台 Worker/HTTP 设备在管理端生成令牌，并通过安全渠道一次性交付。
5. AutoJS6 需要通知访问权限；短信监听还依赖系统授予的短信接收能力。
