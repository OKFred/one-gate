# 生产 D1 迁移闭环实际落地

## 1. 生产故障与恢复结果

2026-08-12 通过 Cloudflare Worker Logs、D1 Console `PRAGMA table_info` 和生产 API 交叉确认：新 Worker 已使用最新 Drizzle 模型，但 GitHub Actions 从未执行 D1 增量迁移。

- `admin_mobile_device` 仍是旧的 9 列，缺少 27 个设备上报字段；新增、关键字检索、在线筛选和定时离线校正均可能 500。
- `admin_mobile_async_task` 仍是旧的 13 列，缺少协议、结果、优先级和抢占相关 13 列；空列表 200 掩盖了结构漂移。

生产已精确执行缺失 SQL 并复核：

- `admin_mobile_device` 已有 36 列，设备事件表和 5 个相关索引齐全；
- `admin_mobile_async_task` 已有 26 列；
- 用户给出的设备新增请求成功，生成记录 `id=1`；基础列表、关键字、在线/离线筛选和精确查询均返回 200；
- 下发 `device.apps.list` 能正常创建任务，并在发布失败时按既有语义写回 `FAILURE/MQTT_PUBLISH_FAILED`。

任务发布的剩余故障不是 D1：对 EMQX WSS 端点的协议级探测收到 CONNACK 5（Not authorized）。当前生产 MQTT 用户名/密码或 Broker 授权需要在 EMQX Cloud 中重置/校正，再同步到 Hodor MQTT 系统配置。

## 2. 代码落地

### 2.1 官方迁移账本

- `server/apps/server/wrangler.jsonc` 配置 `migrations_dir`；
- 新增 `d1-migrations/0000_legacy_schema_baseline.sql` 作为已完成生产 reconciliation 后的过渡标记；
- 新增本地/远程 `db:migrate:worker:*` 脚本；
- 旧 `db:init worker ... migration` 入口改为调用 Wrangler 官方 migration，不再重放全部 legacy `ALTER TABLE`。

历史 migration 保持不变。后续只能追加新的、不可变的 Wrangler migration 文件。

### 2.2 部署前 Schema Contract

新增只读 `d1-contract/worker-schema.sql`，在 Worker 发布前验证：

- 设备 36 列；
- 设备事件表及 5 个相关索引；
- 异步任务 26 列；
- `system_schema_form.source`。

GitHub Actions 顺序改为“迁移 → Contract → Worker deploy → 系统 Schema 数据同步 → Pages”。迁移或 Contract 任一步失败都会阻断新 Worker。

### 2.3 失败显式化与部署密钥

- 全量 Worker 初始化仍用于空库，但现在会累计失败文件并最终抛错，不再输出成功退出码；
- Wrangler 子进程改为参数数组调用，避免拼接 shell 命令；
- 错误由 `unknown` 窄化，移除本次触达处的 `any`；
- `MOBILE_SENSITIVE_DATA_KEY` 纳入 Worker 部署 secrets；GitHub 仓库未配置该 Secret 时，部署应明确失败。

## 3. 验证

- 服务端 `tsc --noEmit -p apps/server/tsconfig.json`：通过；
- 本次 TypeScript 变更 ESLint：通过；
- Prettier：通过；SQL 使用仓库既有格式；
- Python SQLite 手动迁移回归：通过，旧设备数据保留，设备 36 列、任务 26 列、事件表和索引齐全；
- 当前完整 DDL 执行 Schema Contract：通过；
- `git diff --check`：通过；
- Vitest/tsgo build：当前 WSL 复用了 Windows `node_modules`，分别缺少 Linux Rollup 与 TypeScript native 可选包，进程在测试收集/构建启动前失败；不是测试断言或 TypeScript 诊断失败。

## 4. 与计划的差异及后续

- 生产恢复使用精确 SQL，而不是旧全量 runner，避免重复列和部分迁移永久卡死。
- 过渡 baseline 是空操作标记；新建空 D1 仍先执行全量初始化，再应用官方 migrations。后续若将全量建库也统一到 migration，应另做可重复的完整 baseline，不修改已应用的 `0000`。
- 本轮没有改变 HTTP/MQTT 协议、前端行为或任务补偿语义。
- 后续优先处理 EMQX 凭证/授权；其次增加 Worker 安全结构化错误日志，只记录 requestId、cf-ray、错误分类和脱敏 cause，不把 SQL、参数或敏感字段返回客户端。
