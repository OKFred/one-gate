# Cloudflare 用量首页体验优化

## 目标与范围

从最新 main `05063a3b` 创建 `codex/cloudflare-usage-ux`。首页优先回答用量、额度占用、费用与是否需要关注；官方来源、完整口径和采集诊断按需展开。增加 1、3 天，保留 7、30 天。沿用现有权限、身份隔离、采集调度和数据库结构。

## 信息层级

- 顶部保留账号、最近更新时间、简短同步状态、刷新与 AI 入口。权限不足继续显示欢迎页。
- 官方费用按币种、账期和费用口径分组，默认只显示汇总；明细及账单说明折叠。未知费用保持未知。
- 图表与紧凑指标卡突出已用、额度、占比和风险。未知额度、估算、过期及超限状态不能因收纳而隐藏。
- 指标完整名称、统计周期、重置时间、来源和原始原因移入详情。完整表格、覆盖说明与调度信息默认折叠。
- 使用现有 MUI 组件、主题语义色和中英文文案；支持键盘和窄屏。

## 时间范围与图表语义

1/3/7/30 天是包含今天的 UTC 自然日，仅筛选趋势，不把账期总量或费用错误改成所选几天的总量。

- 日指标：官方逐日用量折线。80% 为预警参考线，100% 为当前每日额度参考线；没有历史套餐版本，不声称各历史日额度相同。
- 账期／自然月指标：当前周期累计用量的观测折线。不能把所选窗口的逐日量求和冒充整期累计，也不能把原 API 按 ChargePeriodStart 标记的累计条目当成采集日。
- 在现有 `cumulative_snapshot` 历史中新增明确的 `quota-observation:` 来源，记录可信当前周期指标在采集日的累计值。每天幂等更新同一观察，保留来源区别，不回灌或补造过去的观察；同时为相同主键去重，兼容 PostgreSQL 的 UPSERT 规则。
- 首次没有累计观察时，使用当前已知用量单点，明确累计历史尚不足。当前容量仅显示当前量与容量线，不累计为 GB-month。
- 仅对有限正额度、可靠质量和已知额度类型画线。内含量、硬上限、容量使用不同标签。未知额度不画线。
- 日期缺口和 null 断线，单点仍可查看；不会把缺失补成 0，也不混加 daily_usage 与 cumulative_snapshot。

## 数据与安全

后端 days 枚举扩为 1/3/7/30，复用原查询算法和 OpenAPI 生成类型。新增观察使用现有表和历史类型，无 DDL／迁移、权限或 Secret 变化。观察只写规范化指标值，不记录凭据或原始账单。保留原子发布、租约隔离与失败重试。

## 验证

验证短范围参数与 UTC 边界；三种数据库中的观察幂等、主键去重和发布回滚；日／月／容量图表、未知额度、缺口、单点及超过 100%；费用分组、详情折叠、状态可见、权限与身份变化、窄屏／明暗主题及键盘。区分代码测试、本地模拟预览和生产验收；后续沿用本对话已确认的 PR、CI、合并与发布流程，不扩大到其他业务或资源配置。
