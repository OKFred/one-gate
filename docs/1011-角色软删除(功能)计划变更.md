# 角色软删除计划变更

## 范围

从实施时最新的 `one-gate/main` 创建 `codex/role-soft-delete`。本轮只新增系统角色软删除资源；用户、邮件模板、任务和 Cron 暂不迁移。用户角色分配、部门引用和角色权限管理只修改本轮必需的引用保护。

## 行为冻结

- 固定 30 天回收站、15 秒本人且仍有删除权限的撤销；不新增到期列。
- 超级管理员角色不可删；有任何用户引用即阻断，禁用用户也计入。
- 保留权限配置和部门范围；恢复保留原启用状态，不恢复已移除权限或用户绑定。
- 删除后的名称可复用；恢复遇重名或部门范围不可用时拒绝。
- 部门软删除排除已删除角色引用；部门永久清理仍检查全部角色。
- 永久清除以原子操作同时处理角色与其所属权限绑定。
- 所有恢复失败及未知结果沿用现有规则，不自动重试写入。

## 阶段与完成门槛

1. **数据与安全阶段**：迁移演练、新空库初始化、活动查询、引用与权限绑定并发测试通过后，才能进入生命周期整合。
2. **生命周期阶段**：Node/Worker 下删除、恢复、撤销、关联清理和部门协作全部通过，资源注册同时驱动回收站与调度。
3. **页面与交付阶段**：角色页面、通用 CRUD、错误矩阵和真实后端联调通过；运行格式、前后 TypeScript 对比、构建及差异检查，补实际落地记录。

不以单一环境或 mock 通过代替完整验收。生产部署保持独立私有流程；发布时暂停相关写入、备份、迁移及验证成功后再开放。
