# AutoJS6 短期运维屏幕截图实际落地

## 落地边界

- 在 `/admin/mobile/device` 的设备详情抽屉“短期运维 → 设备信息”增加“获取截屏”。
- `device.screen.capture` 由 Termux Node 运维执行器直接处理，不启动 AutoJS、不进入 MQTT v2 业务任务队列，也不暂停或抢占前台任务。
- 截图仅经当前短期运维 WSS 从设备转发到当前浏览器；未增加 HTTP 接口、D1 迁移、R2/S3 配置或 PC 代理。
- PNG 不写入 D1、对象存储、日志、状态目录或审计正文。Android `FLAG_SECURE` 页面仍遵循系统黑屏规则。

## 手机端

- 新增可信只读操作 `device.screen.capture` 和截图能力声明。
- 使用固定命令 `su -c "nice -n 10 screencap -p"`；进程捕获限时 10 秒，运维请求限时 15 秒。
- 校验 16 MiB 大小上限、PNG 签名、IHDR、屏幕尺寸和 SHA-256。
- 图片使用 `uint32be(headerLength) | UTF-8 JSON header | PNG bytes` 单二进制帧；控制帧仍限制 64 KiB。
- 同一设备最多一个截图请求。发送前后检查 WSS 积压，积压时返回 `SCREENSHOT_TRANSFER_BUSY`；发送完成后只返回元数据并释放二进制引用。
- 截图走现有低并发只读运维通道，与写操作和日常前台任务生命周期相互独立。

## Durable Object 与审计

- Durable Object 只接受设备角色发送截图二进制；操作员二进制以 `1008 / OPS_BINARY_NOT_ALLOWED` 关闭。
- 二进制头必须匹配当前会话、当前 `EXECUTING` 的 `device.screen.capture` 请求；通过条件更新保证一个请求只能接收一个二进制帧。
- 二进制仅转发给当前操作员 WebSocket。审计累加图片帧与终态 JSON 的响应字节数，结构化终态继续加密保存，但 PNG 正文不落库。
- 终态审计更新保持幂等，迟到或重复终态不会覆盖已经完成的记录。

## 管理端

- WSS 建立后自动读取设备能力；旧客户端未声明 `device.screen.capture` 时按钮保持禁用并显示提示。
- 点击后显示加载状态并禁止重复请求。浏览器复核帧大小、会话/请求标识、PNG 签名、元数据和 SHA-256 后才创建 Blob URL。
- 页面显示截图预览、尺寸、大小和捕获时间，并提供“下载原图”。新截图成功后替换旧截图。
- 关闭会话、关闭组件或切换设备会撤销 Blob URL；失败统一使用 Snackbar，无原生 `alert/confirm`。
- 新增中英文截图词条；多语言扫描无缺失键。
