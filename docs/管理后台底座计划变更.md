# 管理后台底座改动范围

本项目中管理后台的基础配置（底座）模块进行了重大的重构与重命名，使其符合“架构重构（三层解耦）”的规范。具体改动范围如下：

## 1. 模块重命名与目录迁移
- 原有的 `admin/src/base/config` 模块已被重命名为 `admin/src/base/sys_config`。
- 与之相关的数据库表名从 `base_config` 修改为 `base_sys_config`。
- 前端路由与 API 目录同步由 `base/config` 变更为 `base/sys_config`。

## 2. 缓存抽象层的剥离与重组
- **系统配置 (`sys_config`)**：由于系统配置的数据不频繁变动且需要强一致性约束，去除了旧有的缓存机制，所有的读写操作直接落库查询。
- **企业业务配置 (`biz_config`)**：新增 `enterprise/src/base/biz_config` 模块。该模块承载租户维度的业务级配置。
  - 使用了封装的缓存抽象层（`kv`，来自 `@hodor/core/middleware/cache`）。
  - 增删改操作时，遵循“先落库、再清理缓存，下次读取时自动重建缓存”的最终一致性策略。
  - 缓存 Key 设计为 `biz_config:{tenantId}:{namespace}`。
- **用户个人配置 (`user_config`)**：新增 `personal/src/base/user_config` 模块。该模块承载用户维度的偏好级配置（例如界面主题深浅色等）。
  - 同样接入了缓存层，缓存 Key 设计为 `user_config:{userId}:{namespace}`。
  - 数据模型中采用 `userId` 作为核心隔离字段。

## 3. 跨包依赖解耦
- 各模块通过 `@hodor/admin/common/registry` 进行服务注册和调用解耦。
- `biz_config` 和 `user_config` 依赖 `sys_config` 里的机制规范，但在物理包上严格隔离，相互之间不跨包 import 底层 service。

## 4. 全局数据同步
- 对 `initMenu.ts`、`initPermissions.ts`、`constants/permissions.ts` 等全局种子数据进行了更新，补充了 `enterprise.base.biz_config` 与相关的路由/权限节点。
- 对 `drizzle-kit` 配置文件所需的 Schema 导出进行了梳理。
