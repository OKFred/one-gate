# 禁用角色鉴权实际落地

## 实际行为

每个 JWT 请求读取数据库中的当前启用角色，以此计算角色 ID、超级管理员身份和数据范围。禁用或不存在的角色不再贡献 ALL/CUSTOM 范围；旧缓存不能重新引入其权限。用户和角色管理页面仍可查看禁用角色的绑定与权限配置，重新启用后既有配置继续生效。

普通权限读取在同条 SQL 中连接并过滤角色启用状态，移除最多 10000 条的管理列表中转。角色 1 的快捷授权必须确认该角色存在且启用；保留原有管理端禁止停用角色 1，以及启用超级管理员的原有权限语义。API Token 继续采用令牌自身的独立权限。

权限缓存采用格式版本 2，绑定本请求的有效角色快照和查询前捕获的全局版本。旧格式、角色变化和迟到写回均不能冒用新的角色状态。缓存读取失败回退数据库且不写入猜测的版本；数据库角色查询失败拒绝继续使用缓存。缓存读写错误输出固定结构化事件，不输出底层错误详情。

角色更新时间在单条 SQL 中单调递增，覆盖同毫秒连续切换和时钟回退。公共鉴权新增一次按当前绑定 ID 限定的角色查询；缓存仍能省去权限加载，冷路径不再读取全站角色管理列表和另一次范围查询。未进行吞吐量压测。

## 与计划差异

- 五个实现文件按计划完成；registry 从 role utils 自动推导，无需修改装配或接口声明。
- 新增两套集成测试，共 32 项。第一轮复盘后补充正常缓存命中、Node 无执行上下文、KV 写失败、数据库角色查询失败的验证。
- 同时收紧范围值和自定义部门数组的类型检查，异常旧值采用安全范围，不扩展业务表迁移。
- 部门引用保护没有改动，原有禁用角色引用阻止删除的测试继续通过。
- 没有 API、菜单、数据库结构或前端接口变化，因此无需生成 OpenAPI 类型或数据库迁移。

## 迁移与发布验收

本轮不涉及数据库迁移，无需迁移演练。PR CI、dev 合并、自动 Worker/Pages 发布以及只读线上验收作为独立阶段，其提交、版本和结果记录在本轮 PR 及忽略目录的上线验收报告中。上述本地测试不替代线上角色停用实验；线上验收不更改真实角色、权限或业务记录。

## 保留边界与后续建议

读取到禁用状态后的新鉴权请求拒绝该角色，已完成角色快照读取的在途操作仍可能完成。本轮没有提供权限映射跨节点线性化撤销；现有全局 KV 版本仍具最终一致性。若需要更强撤销保证，应另行设计数据库授权版本或事务内授权，不通过增加缓存失效调用声称完成。

根目录六项既有 TypeScript 错误位于三个 mobile 仓储及两个历史测试脚本：三项 SQL 类型错误、一项非模块顶层 await、两项旧移动模块导入缺失。本轮无新增未修类型错误。
