# AutoJS6 重复部署阻断优化实际落地

## 实际结果

- Node Server 从设备心跳解析当前版本、制品摘要、环境和环境修订，普通部署与回滚在创建审计记录前拒绝完全相同的目标组合。
- 摘要不一致时不判定为无变化，仍允许通过完整部署流程修复设备侧内容。
- 管理页每 5 秒同时刷新发布、环境、部署历史和设备详情，展示当前运行组合。
- 页面在目标无变化或存在未终结部署时禁用部署；回滚目标无变化或存在未终结部署时禁用回滚。
- 最新部署刚进入终态但设备下一次心跳尚未到达时，页面按 `SUCCEEDED` 的目标组合或其他终态的前一健康组合即时推导当前状态，消除轮询时间差。
- 部署和回滚共用同步提交锁，确认窗口打开时也不能产生第二次提交。
- 生产验收发现并修正 Pages `version.json` 标记上一个提交的问题；Actions 现在用当前 `${github.sha}` 同时盖章 Worker 和三套 Pages。

## 与计划的差异

### 增加的工作

- 第一轮复盘发现仅依赖设备详情仍存在“部署终态已到、心跳未刷新”的短窗口，因此增加部署中锁定和最新终态结果推导。
- 在纯函数测试之外增加 `apply`、`rollback` 服务级测试，明确验证阻断发生在数据库写入和 MQTT 下发入口之前。
- 线上功能页已经更新但静态版本文件仍显示前一提交，因此移除 pre-commit 的旧 HEAD 盖章，并把 Pages 盖章并入现有 Actions 部署版本步骤。

### 未采用的工作

- 未增加数据库字段或迁移；设备心跳和不可变部署历史已能提供所需状态。
- 未修改 MQTT Topic、命令载荷、supervisor 或手机客户端。
- 未增加浏览器原生 `confirm`、`alert` 或重复错误弹框，继续复用现有自定义确认组件和全局 Snackbar。

## 本地验证

- Server：63 个测试文件通过，347 个测试通过、3 个跳过；部署阻断定向测试 14 个、版本盖章定向测试 5 个通过；TypeScript 构建通过。
- Platform：Admin TypeScript 与生产构建通过；原生浏览器弹窗扫描通过；多语言扫描缺失键为 0；本次新增前端文件的定向 ESLint 通过。
- 全仓 Platform ESLint 仍有历史基线问题，主要是既有空 `catch {}` 与旧 `any`；本次没有新增 `any` 或新的定向 ESLint 错误。CI 当前以构建、原生弹窗扫描和 OAuth E2E 为发布门禁。
- `git diff --check`、本次文本文件 LF 与 UTF-8 无 BOM 检查通过。
