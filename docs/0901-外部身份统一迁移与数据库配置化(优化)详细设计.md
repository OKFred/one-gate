# 外部身份统一迁移与数据库配置化详细设计

## 背景与目标

Hodor 当前同时维护本地密码、GitHub、飞书和 one 身份中心四套主认证入口。GitHub、飞书的
Provider 适配器、Token、档案、组织或租户准入规则与 one 的身份上下文重复，且 Hodor 的 OIDC
连接仍由多项 `SSO_*` 环境变量驱动。重复实现增加了 Secret 治理、回调白名单、账号绑定和故障排查
成本，也使不同部署者必须重复配置同一类业务参数。

本次目标是让 one 成为 GitHub、飞书外部身份的唯一所有者；Hodor 只保留本地密码和标准 OIDC
SSO。所有可持久化的 SSO 连接参数进入 Hodor 权威数据库，仅运行时绑定和数据库无法自我保护的
根密钥留在部署环境。改造后仍保持“主认证 → TOTP → 菜单与业务”的安全顺序。

## 范围与非目标

- 新增一份无外键的 Hodor SSO 连接配置，支持草稿、连通性测试、启用和停用。
- 提供仅管理员且已通过 TOTP 才能调用的配置管理 API。
- 先以数据库优先、旧环境配置兜底完成兼容迁移，再删除 `SSO_*` 环境变量依赖。
- 删除 Hodor 直连 GitHub、飞书和未实现的微信入口；外部身份改由 one 登录页和账号页管理。
- 保留历史 OAuth 表、migration 和数据，确保一个发布观察期内可回滚旧 Worker/UI。

本次不迁移或解密历史 OAuth Token、完整档案和绑定，不按邮箱自动合并身份，不删除旧 Provider
应用，不撤销 Provider 授权，不修改 one 的用户数据，也不改变 Hodor JWT、RBAC、TOTP、设备回调或
机器凭证协议。

## Bounded Context 与依赖方向

继续使用 `admin.system.auth.sso` 垂直切片：

- domain：连接状态、版本、issuer、redirect URI、HTTPS 和配置转换规则。
- application：读取、保存草稿、测试、停用和解析活动配置用例；依赖配置 Repository、OIDC
  Probe、Clock 和审计端口。
- infrastructure：Drizzle Repository、Discovery/JWKS Probe、根密钥适配器和运行时组合。
- interfaces/http：POST Schema、管理员/TOTP 上下文适配和稳定错误映射。

运行时不得再从业务用例直接读取 `SSO_*`。兼容期的环境回退只存在于基础设施配置来源适配器，且
数据库中存在任意配置行后立即停止回退，避免形成两个长期事实源。

## 配置分类

### 持久化配置

新增 `system_sso_connection` 单例表，固定 `id = 'default'`，字段包括：

- `issuer`、`client_id`、`audience`、`allowed_tenant_id`。
- `redirect_uris_json`，保存规范化且去重后的精确 URI 数组。
- `status`：`draft | ready | disabled`。
- `config_version`、`last_tested_at_utc`、`updated_by_user_id`。
- `create_time_utc`、`update_time_utc`。

表不声明 `FOREIGN KEY` 或列级 `REFERENCES`。应用层验证修改者存在、版本匹配和状态转换；
`config_version` 使用条件更新实现乐观并发控制。保存配置会强制回到 `draft`，只有当前版本通过
Discovery/JWKS 测试后才能变为 `ready`。

### 运行时与 Secret

- `NODE_ENV`、D1 绑定和 Node 本地数据库路径继续由运行时提供。
- SSO PKCE verifier 使用 `HODOR_AUTH_MASTER_KEY` 加密；该根密钥不得入库。
- 兼容期允许读取旧 `OAUTH_SENSITIVE_DATA_KEY`，但只记录使用了 legacy key，不记录值或摘要；最终
  部署要求 `HODOR_AUTH_MASTER_KEY` 并停止读取旧名称。
- `SSO_ISSUER`、`SSO_CLIENT_ID`、`SSO_AUDIENCE`、`SSO_ALLOWED_TENANT_ID` 和
  `SSO_ALLOWED_REDIRECT_URIS` 仅保留一个发布周期的回退能力，最终从类型、Wrangler 和 CI 中移除。

## 配置管理与失败语义

新增以下 POST 接口：

- `/admin/system/auth/sso/config/get`
- `/admin/system/auth/sso/config/save`
- `/admin/system/auth/sso/config/test`
- `/admin/system/auth/sso/config/disable`

所有接口均要求有效 Hodor Token、匹配当前 Token 的 TOTP 门禁 Cookie 和平台管理员身份。`save` 使用
`expectedVersion`；首次创建要求 `0`，后续更新要求当前版本。版本冲突返回 409。`test` 只测试数据库
中的当前草稿，验证 HTTPS issuer、OIDC Discovery、JWKS、issuer 一致性和 redirect URI 安全性；成功
后原子标记同一版本为 `ready`，配置在测试期间被修改则返回 409。`disable` 使用条件更新停用连接。

配置缺失、草稿、停用、数据库异常或 Discovery/JWKS 失败均 fail closed。兼容期仅当表中没有配置行
时才读取完整旧环境配置；任意变量缺失时不做部分合并。密码登录保持可用，SSO 发起接口返回现有
`SSO_CONFIGURATION_ERROR` 安全文案。

## 外部身份退出 Hodor

从 Hodor 活动表面删除：

- `/admin/system/auth/oauth/login/url`
- `/admin/system/auth/oauth/login/callback`
- `/admin/system/auth/oauth/account/url`
- `/admin/system/auth/oauth/account/callback`
- `/admin/system/auth/oauth/binding/unbind`
- `/admin/system/auth/oauth/binding/profile`
- `/admin/system/auth/wechat`
- 前端 `/oauth/callback`、GitHub、飞书和微信按钮及账号档案交互。

这些路径由全局 Not Found 返回统一 JSON 404，不增加过渡 410。现有 `/sso/*` 登录、绑定、解绑和摘要
保持请求响应兼容。用户资料删除 `githubUsername` 和 `oauthBindings`，前后端及 OpenAPI 生成类型在同一
发布中同步。

`system_user_oauth`、`system_oauth_state` 及历史 migration/Schema Contract 保留。活动代码不得新增
读写，部署前后只读统计行数应保持不变。

## 安全、日志与回滚

- 配置 API 不接收或返回 one Provider Secret；Hodor 只保存公开 OIDC Client 参数。
- redirect URI 精确匹配；生产仅允许 HTTPS，开发仅允许 localhost/loopback HTTP。
- 出站 Probe 只记录 requestId、host、path、状态、耗时和稳定错误分类，不记录 header、query、JWKS
  正文或 Token。
- 配置保存、测试成功、停用和版本冲突记录操作者、旧/新版本和结果分类，不记录具体配置值。
- 旧 Provider 应用、旧 Worker Secret 和历史表保留一个发布观察期。需要回滚时部署上一版 Hodor；
  不恢复、转换或删除数据库数据。

## 成功标准与测试矩阵

- 数据库配置优先；兼容期仅空表回退；最终构建不再引用 `SSO_*` 和 Provider 环境变量。
- 配置表在空库和上一版数据库上迁移成功，`PRAGMA foreign_key_list` 为空。
- 保存强制 draft，测试成功才 ready；版本冲突、配置漂移、Discovery/JWKS 故障均 fail closed。
- Hodor 登录页只显示密码和 Identity Center，SSO 回调后仍进入 TOTP 而非提前加载菜单。
- one 中 GitHub/飞书登录后签发的 `amr` 经 OIDC 进入 Hodor 绑定摘要。
- 所有旧 OAuth/微信接口返回 JSON 404，历史 OAuth 表无新增写入。
- 日志和错误不包含 Secret、Token、授权码、PKCE verifier、手机号、完整身份档案或原始配置。
