# One Gate 开源迁移详细设计

## 范围

建立独立的 `OKFred/one-gate` 仓库，默认分支为 `main`，使用 MIT 许可证。业务代码以原开发主线的冻结快照为准；不增加新业务功能，不改动线上服务、数据库或域名。内部 `@hodor/*` 包名保持兼容。

## 历史边界

以选定的 2025-08-30“feat: 脚手架搭建”提交作为无父节点的新根，保留其快照及后续开发提交。保留节点共 1,181 个，原有 121 个合并节点；一处后续合并引用了边界之前的父节点，切断该引用后剩余 120 个多父节点。保留范围内的父子关系、提交内容、作者及时间不变；根之前的祖先不进入新仓库。历史清理允许删除敏感文件、替换敏感内容，但不裁剪因此变空的节点。

完整原始历史、校验和、引用清单、旧新提交映射及清理报告保存于仓库外的私有备份。候选库仅发布清理后的 `main`，不复制标签、旧分支、PR 引用、替换引用或原始对象。

## 公开内容与凭证边界

同时扫描新根快照、全部保留历史和最终工作树。检查私钥、令牌、密码、运行数据、部署标识及私人运维记录。扫描报告与替换规则不得进入公开库。自动扫描为零不代替人工审查。发现仍有效且需要处置的凭证时，先处理公开阻塞，不擅自轮换生产凭证。

部署示例使用占位值和本地地址；真实资源由部署者单独配置。文档更新项目名称、实际启动命令、许可证和迁移边界，保留第三方归属信息。

## CI 与生产

公开 CI 使用 GitHub 托管 Linux runner、只读仓库令牌和隔离的测试配置，仅执行安装、检查、测试和构建。生产部署与公开 CI 分离，不迁移原仓库的 Secrets、自托管 runner 或自动部署逻辑。

## 发布与恢复

先验证备份可恢复，再在隔离候选库清理历史。新仓库先以私有状态校验推送和 CI，通过后公开并以匿名方式验证。原仓库维持私有，在新仓库验收后更新迁移说明并归档。原目录及未跟踪文件保留。恢复依赖私有 bundle，不将旧历史重新推入公开仓库。历史边界调整时，先备份并验证候选库；将使用旧边界的公开仓库转为私有归档，再独立建立同名仓库，避免在新仓库保留上一版的提交对象。仓库名、main、MIT、公开 CI 及业务代码保持一致。

## 验证

检查根数量、节点映射、合并拓扑、引用与对象可达性、敏感扫描、最终代码差异。分别记录 TypeScript 前后诊断、Node/Worker 测试、前端构建、Playwright、格式及 `git diff --check`。历史代码的运行能力不作追溯保证；当前源码必须通过约定检查。迁移验收不等同于生产功能验收。
