# 软删除与 30 天回收站详细设计

## 范围

从最新 dev 建立 codex/soft-delete-retention。仅交付公共机制与部门试点：软删除、管理员回收站、恢复、超级管理员提前清除、Worker/Node 到期清理。其他业务实体不迁移。

## 数据与状态

部门新增 is_deleted INTEGER NOT NULL（Drizzle boolean，无数据库默认值）、deleted_time_utc INTEGER、deleter_id INTEGER。新增由服务端显式写 false/null/null，普通请求不接受删除字段。普通查询和编辑只处理未删除记录。删除保留原 ID、内容与启用状态，首次删除计时，重复删除不续期。恢复清空删除字段；满 30 × 24 小时不再可恢复。

活跃名称采用 WHERE is_deleted=0 部分唯一索引，删除释放名称，恢复重名拒绝。禁止删除仍被未删除子部门、全部用户或角色部门范围引用的部门，包含禁用记录。彻底删除检查所有物理存在子部门，先子后父。引用创建/更新与删除均采用单条条件 SQL，Service 预检查只用于友好报错。用户显式清空部门写 null；角色部门数组写入必须有效。成功变更按既有机制使权限缓存失效。

## 公共机制与接口

公共包提供字段工厂、保留期计算与清理接口，不导入业务实现。固定注册部门清理适配器，不扫描表、不接受客户端物理表名。

现有部门 POST /delete 契约不变。新增 POST /admin/maintenance/recycle-bin/list、/restore、/purge，资源类型仅 department；恢复和清除请求携带 id 与 expectedDeletedTimeUtc。列表需回收站读取及部门读取权限，恢复需回收站恢复及部门编辑权限，提前清除必须为当前数据库身份认定的 isSuperAdmin。返回明确的状态、期限、父部门、名称、引用冲突。

管理员回收站展示部门名称、删除人、删除时间、到期时间，支持搜索、分页、恢复和受限彻底删除。使用既有组件/确认弹窗和 dayjs，提供中英文文案，不修改全站共用删除提示。同步菜单、权限、OpenAPI 类型。

## 清理与旧快照

复用 Worker/Node 每分钟驱动，每轮每类最多 100 条，条件 DELETE 原子检查状态、期限、引用。失败下轮重试，输出删除数、超期数量、最早超期时间及结构化错误，不复制业务内容；空轮次安静。满 30 天失去恢复资格，后续调度物理清除，积压不得静默。

删除原部门 exportDeletionRecord 调用，不再写完整快照。旧 compliance_archives 仅 source_system=self、source_database=self、source_table IN (department,system_department) 纳入历史清理，以 create_time_utc+30天为期限，不重新计时，不回灌，不处理其他来源。

## 迁移与发布

定向生成最终 DDL，保留历史 migrations（现有全量 db:generate 会清空该目录，不能直接使用）。通过换表保留旧列/ID/自增高水位并回填0/null/null，建立状态与索引约束。D1使用新增编号迁移及契约检查；Node用指定迁移脚本、写事务、成功标记、重复执行保护和失败回滚。发布前暂停相关写入；迁移与新版验证成功后开放。旧代码不会过滤软删除，不能直接回退旧版服务后开放访问。

## 数据保护边界

30天是误删恢复目的的业务保留窗口，不是GDPR统一期限。适用删除权且无保留例外的请求需及时处理，不能强制等待30天；通常一个月答复期限不等于允许固定延迟。提前清除只处理本期部门资源，不代表完成全站个人数据删除。

备份、日志、其他业务及第三方副本分别治理。D1 Time Travel有独立历史窗口，不能声称所有备份在删除后第30天消失。备份恢复须依据恢复点之外保存的删除请求记录重新落实删除，再开放访问；只运行到期清理不足以避免旧数据复活。本期不新增整条记录归档。

## 验收

覆盖旧库迁移/回滚、查询隐藏、请求字段限制、重复名称生命周期、引用双向并发、过期边界、恢复/清除竞争、旧页面版本冲突、超级管理员身份、历史来源隔离、批量/失败重试、Node/Worker驱动与UI授权。执行变更文件格式化、前后类型诊断对比、相关测试构建及git diff --check；代码验证、迁移演练、上线验收分别记录。

## 发布维护入口

现有 dev 部署流水线会先迁移 D1，再替换正式 Worker。首次执行 0013 前，以显式部署的独立维护入口暂停 HTTP 请求和新的分钟任务，保留现有 Durable Object 类导出及绑定。该入口返回带 Retry-After、no-store 和固定维护标识的 503，不访问数据库，也不自动超时开放；正常 Worker 入口不增加常驻维护开关。

确认维护响应生效并为在途请求留出排空时间后记录 D1 Time Travel 恢复点，再合并 PR。流水线通过两份迁移及结构契约后，正式 Worker 替换维护入口即恢复后端服务，随后发布前端并完成验收。若流水线在正式替换前失败，保留维护状态，按迁移实际进度处理，不能直接回退到不识别软删除的旧服务。
