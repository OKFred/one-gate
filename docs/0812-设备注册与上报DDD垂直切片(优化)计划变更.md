# 设备注册与上报 DDD 垂直切片计划变更

## 1. 计划目标

在 `server/packages/admin/src/mobile/device` 内建立第二个 DDD 垂直切片，拆解近千行 `service.ts`，保持设备管理、上报、MQTT、D1 和前端行为兼容。

## 2. 预计文件变更

### 2.1 新增

- `domain/device.ts`：在线、Presence、设备信息与事件纯规则。
- `domain/metadata.ts`：reportedExtra 与自定义元数据纯规则。
- `application/error.ts`：应用错误。
- `application/ports.ts`：Repository、Crypto、Clock 端口及应用记录类型。
- `application/device-center.ts`：设备注册、上报、事件和维护用例。
- `infrastructure/repository.ts`：Drizzle Repository 适配器。
- `infrastructure/crypto.ts`：现有加密/令牌实现适配器。
- `infrastructure/container.ts`：默认依赖装配。
- `interfaces/http/error.ts`：HTTP 错误映射。
- `interfaces/http/report-token.ts`：请求头令牌适配。
- `facade.ts`：稳定应用门面。
- Domain、Application 和 HTTP 兼容性测试。

### 2.2 调整

- `model.ts`：继续集中 Drizzle 与 JSON Schema，仅在需要时引用领域常量。
- `service.ts`：缩减为 HTTP Schema、adapter、权限和 facade 调用。
- `index.ts`：路由行为不变。
- `mqtt/listener.ts`：改依赖设备 facade。
- `async-task/infrastructure/container.ts`：改用 facade 任务目标查询。
- `apps/server/src/worker.ts`：改依赖设备 facade。

### 2.3 删除或兼容收口

- 根 `repository.ts`、`crypto.ts`、`metadata.ts` 的实现迁入对应层；若不存在仓库外公共引用则删除，否则仅保留无业务逻辑的兼容导出。

## 3. 公共接口

- HTTP API 数量、键名、路径、POST 方法、权限及 JSON Schema 不变。
- MQTT v2 Topic/载荷和设备令牌头不变。
- facade 保留现有跨模块函数的名称与行为，并新增任务目标与日志标签的最小查询能力。
- 不修改 OpenAPI 生成文件、前端 API、权限、菜单和翻译。

## 4. 数据与部署影响

- 不修改 Drizzle 表定义。
- 不生成或执行 DDL/D1 migration。
- 不修改 Cloudflare bindings、环境变量、EMQX 或 AutoJS6。
- 本轮提交后按现有 GitHub Actions 正常部署即可。

## 5. 验证顺序

1. Windows 服务端 TypeScript 基线。
2. 新增 Domain 测试并固定规则。
3. 新增 Fake Ports 应用测试。
4. 迁移 service、MQTT、Worker 和 async-task 调用方。
5. Windows 定向 Vitest、TypeScript、服务端 build。
6. 变更文件 ESLint/Prettier。
7. API 对象、路径、Schema、权限与跨模块 import 静态复核。
8. `git diff --check`、编码/行尾、no-any 和最多五轮复盘。
9. 输出 `docs/0812-设备注册与上报DDD垂直切片(优化)实际落地.md`。
