# 硬盘资产采集接入与模拟验收

## 先登记身份，再采集

1. 在企业资产台账中创建主机 A、主机 B 和硬盘资产。资产 UUID 是长期身份；资产名称、主机、盘符和测点名可变化。
2. 给硬盘添加已核验、高可信标识：WWN 使用 `wwn / storage.wwn`，SN 使用 `sn / storage.serial`。WWN 优先；仅 SN 时必须同时匹配精确型号。占位值不能用于自动关联，桥接器不提供可靠身份时保持未解析。
3. 在硬盘安装记录中选择当前主机。迁移时使用已有的替换安装关系操作，设置准确 UTC 生效时间，旧安装结束时间与新安装开始时间相同。不要创建第二份硬盘台账，也无需按新盘符重建测点绑定。
4. 采集主机各配置一次其主机资产 UUID、企业和只读身份目录凭据。令牌同时需要 `enterprise.asset.mapping:read`、`enterprise.asset.telemetry:read` 和有效企业授权；普通旧 mapping 权限不会自动读取硬件标识。企业及有效所有者须保持启用。API token 独立授权，创建人的角色撤权不会自动撤销该 token；需要停用采集访问时，显式撤销令牌、移除令牌权限或撤销企业 grant。
5. 先成功刷新目录，再让采集器处理新样本。目录及原始硬件身份是私有控制面数据；不能放进公共温度缓存、MQTT、云端原始归档或 Grafana。看板使用不透明 UUID 和规范指标 `temperature_c`。

新权限无需数据库结构迁移。部署到已有 SQLite/D1 后，由超级管理员受控调用 `POST /api/v1/admin/maintenance/init/db`，请求 `{ "reset": false, "skipSuper": true }` 同步种子；该入口也会同步菜单、翻译和地区等基础配置，应先核对环境与同步范围，再按发布安排执行。PostgreSQL 使用 `pnpm run db:seed:postgresql` 先检查，再显式添加 `--apply` 补缺。`sync:permissions` 只生成前端常量，D1 结构初始化也不会同步权限种子，合并 PR 不会代替这一步。本轮仅在隔离测试库验证种子，现有台账、标识和安装页面继续管理主数据。

## 时间和故障边界

安装区间为 `[开始,结束)`：T 时刻迁移，T-1 属于 A，T 属于 B。关联按原始逐指标采样时间判断，在首次持久化入队前冻结。重试、重启和离线补报继续使用原关联，不重新套用最新安装关系。

目录租约为 15 分钟。断网时仅能在原租约内继续新关联；明确撤权立即清除该身份缓存。完全离线时无法立即获知撤权，最长存在 15 分钟识别窗口。无目录时仍保留原始温度，不能猜测资产；目录过期时不得生成新的 matched 关联。

身份表目前没有历史版本：未冻结且早于标识创建/修改的旧样本保持未知。仅 SN 还受资产资料最近修改时间限制，避免用新型号解释旧观测。已经冻结的历史关联不重写。需要修复未知历史时，应采用今后独立的可审计回填方案。

## 运行真实 API 的合成夹具

在 `server/apps/server` 目录执行（控制文件路径必须在仓库外且尚不存在，父目录需已存在；下面使用通用示例路径）：

```powershell
pnpm exec tsx scripts/simulate-hardware-assets.ts D:/one-gate-validation/control.json
```

脚本不加载 `.dev.vars`，显式选择内存 SQLite，使用合成用户、企业和短期测试凭据；只监听 `127.0.0.1` 的随机端口。通过真实 `/add`、`/identifierAdd`、`/assign` 服务建立 A/B/D/E，控制文件提供测试接口地址、只读令牌、模拟管理员令牌、资产 UUID 和一次性 `moveRequest`。不要公开控制文件或把它提交到仓库。

采集模拟器应先冻结 A 的 T-1 样本，再使用控制文件 `adminToken` 将 `moveRequest` POST 到 `baseUrl + /enterprise/asset/assign`，然后刷新 B 的目录并采样 T。此迁移带预期版本，只能成功执行一次；重新验收时停止夹具并重启，生成全新的内存库及控制文件。若旧控制文件仍留存，选择新的控制文件名，脚本不会覆盖已有文件。

夹具收到 Ctrl+C 后停止 HTTP 并清除控制文件，内存数据随进程退出消失。它不启动调度器或 MQTT listener，不连接生产数据库，不扫描真实硬盘。两仓库的联调命令和实际结果另见《实际落地》；这不是实盘迁移或线上发布验收。

## 复查证据

至少确认：D 在 A/T-1 与 B/T 的 UUID 一致且归属 ID 不同；A/T 和 B/T-1 不会误匹配；E 占旧路径仍为 E；路径和源指标名改变后用户配置哈希不变；旧队列经过迁移、ACK 丢失和重启仍保持相同输出 ID 与完整关联哈希；多盘分别关联；公共输出没有 SN、WWN、设备路径或凭据。曲线按 UUID + 规范指标归并，保留主机归属分段。
