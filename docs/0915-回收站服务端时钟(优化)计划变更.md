## 实施顺序

1. 新分支与修改前 TypeScript 基线；先完成本文及详细设计。
2. 并行实现通用列表合同、部门最终期限校验与前端生命周期处理。
3. 重新生成 OpenAPI，完成格式修复及前后类型诊断比较。
4. 独立复盘；发现问题先暂存再修复，最多五轮。
5. 完成定向与必要全量测试、构建、实际落地文档、diff 检查。
6. 提交 PR；通过 CI 后合入 dev，核对自动发布和真实只读验收。

## 保持现状与已知限制

数据库结构、30 天固定期限、清理调度、资源注册与权限模型保持现状。旧前端兼容新增响应字段；新版前端缺少可靠时间时禁用旧操作并显示读取失败。单时间戳无法消除网络单程延迟。OS 真实睡眠和备份恢复演练不等同于模拟浏览器验证，交付时分别说明。
