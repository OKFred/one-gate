# 天地图内嵌：计划变更

## 后端

- `server/packages/admin/src/base/map/`：集中请求/响应 Schema、配置读取与用户身份校验、POST 服务及独立路由入口、定向认证/配置测试。
- `server/packages/admin/src/base/index.ts`：挂载 map 模块。
- `server/packages/core/src/types/business.ts`：新增地图业务命名，不新增可分配权限。
- `server/apps/server/src/postgresql-capabilities.ts` 与相关测试：只增加地图配置模块支持。
- 环境示例/部署说明：声明空的可选 `TIANDITU_BROWSER_KEY`，不放真实配置。不新增表、迁移、菜单或权限种子。

## 前端

- 首页以 `view=map` 查询参数区分用量视图和独立地图工作区，入口对登录用户可见，地图退出时卸载。其他首页行为保持。
- 新增独立地图组件与图层/瓦片适配，依赖 Leaflet 与类型声明，更新相应包和锁文件；组件仅在进入地图工作区后加载。
- `platform/packages/ui/src/api/admin/base/map.ts`：共享请求封装，从生成 OpenAPI 推导类型。
- OpenAPI 类型：仅同步本次端点合同。
- 管理端中英文：入口、地图标题、图层、返回、未配置、加载/失败/重试和辅助标签。
- 定向浏览器 fixture 与测试：模拟配置与瓦片不代替真实天地图验收，避免请求真实供应商或使用历史 Key。

## 实施顺序

1. 核对 main 合并状态与旧实现、配置来源，建立分支，输出本设计及计划，采集 TypeScript 基线。
2. 并行完成登录配置接口和地图组件，生成 OpenAPI 后连接真实类型。
3. 执行格式/lint、类型对比、Node/Worker 与浏览器定向验证、构建和复核；修复发现的问题，最多五轮。
4. 补实际落地，按既有 PR/CI 发布流程交付；有已确认配置时再做供应商只读联调。不擅自启用归属未确认的历史 Key。

## 验收与数据边界

代码验证、模拟浏览器、真实供应商和生产发布分别记录。D1 业务数据、原资源绑定、Cloudflare 用量及 AI 功能保持；未配置时显示明确状态，不能宣称真实地图已通过。所有凭据和私有归档证据位于仓库外，报告不写原始值。
