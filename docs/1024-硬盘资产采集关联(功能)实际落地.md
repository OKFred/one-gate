# 硬盘资产采集关联实际落地

日期：2026-10-24。分支 `codex/hardware-asset-linking`，基线 `7ea08c7e`。本轮用户要求模拟验收，不安排实盘迁移。

## 已落地

新增 `POST /api/v1/enterprise/asset/telemetry/catalog` 和 `/resolveBatch`，复用现有资产、核验标识和安装关系，不新增数据表或迁移。目录包含授权租户的高可信硬盘身份及完整安装区间；SQLite/D1、PostgreSQL 都由单条有界 SQL 同时读取数据及权限，空目录仍校验 host；超限整体拒绝。

新增 `enterprise.asset.telemetry:read`，普通旧 mapping 权限不能读取 SN/WWN。机器令牌还需要原 mapping 权限及企业 grant，查询时重新校验令牌、权限、成员、企业和有效所有者。响应为 private/no-store。已同步权限种子、生成的权限常量、OpenAPI、前端 API 封装和中英文业务名称/错误文案。

纯解析复用固定 UUID，按原始观测时间解析半开安装区间，支持 WWN 主证及 SN-only 精确型号、历史生效时间、退役、冲突与固定错误优先级。目录完整内容 SHA-256 与 15 分钟租约分开。共享合成 fixture 固定 UTF-16 排序、JSON 转义、安全整数与 ECMAScript trim 的跨语言行为。

合成 HTTP 夹具仅监听 loopback，使用内存数据库及真实资产新增、标识新增、安装 API，提供跨仓库一次性迁移控制文件。控制文件仅独占创建；写入失败关闭监听并非零退出；只清理由本进程成功发布的文件。

## 与计划的差异

- telemetry 使用独立子域 `model/domain/context/catalog-query/repository/service`，没有向原资产大文件继续堆叠逻辑；不修改旧 tenant/mapping 守卫，而以固定新权限组合原守卫，减少旧授权链路的影响。
- 新增 `catalog-query.ts` 让两种数据库共享单条 SQL 与去重投影。主机、资产 ID 及时间字段在投影时校验，两套驱动只负责执行。
- 未新增资产管理页面，继续使用已有台账/标识/安装 UI；增加接入说明、类型安全 API 封装和权限显示名称。
- 根据采集对话反馈，冻结关联增加安装区间起止字段，并明确无目录时省略扩展、保留温度；规范指标为 `temperature_c`。这些字段纳入完整关联哈希。
- 额外检查测试源码类型（应用 tsconfig 原本排除 spec），修复两处测试 Schema readonly 桥接和三处 fixture 推导/Promise 类型；无业务行为改变。

采集复现入口为 `tools/simulate-hardware-assets.py --one-gate-control <私有control> --output-dir <全新目录>`，完整前提及仅复用安全输入的 Node 桥接命令见采集仓库 `docs/hardware-asset-linking.md`。重复完整验收需要新的 One Gate 内存夹具，不能对已迁移夹具再次运行 moveRequest。
