# 禁用角色鉴权计划变更

## 预计文件

| 文件                                                             | 预计变化                                                                            |
| ---------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `server/packages/admin/src/system/role/repository.ts`            | 按指定 ID 查询有效角色快照，数据范围查询过滤禁用角色；更新毫秒时间在 SQL 中单调递增 |
| `server/packages/admin/src/system/role/service.ts`               | 通过现有 utils 暴露鉴权查询                                                         |
| `server/packages/admin/src/system/role_permission/repository.ts` | 普通角色权限查询在同条 SQL 中限制角色启用                                           |
| `server/packages/admin/src/system/role_permission/service.ts`    | 去除管理列表中转；超级管理员快捷通道确认角色启用                                    |
| `server/packages/core/src/middleware/auth/index.ts`              | 使用有效角色快照构造身份与范围；缓存格式和角色指纹校验；安全版本捕获                |
| `server/packages/admin/src/system/__test/` 下相关集成测试        | 仓储与服务边界、真实 JWT 中间件、热缓存及并发旧包回写回归                           |
| 本组详细设计、计划变更、实际落地文档                             | 记录设计、验证结果、复盘次数和差异                                                  |

`register.ts` 已展开 role utils，registry 接口通过类型推导取得新增能力，预计无需重复手写声明。若发现菜单等调用方继续直接使用管理角色集合，应核对其最终权限查询是否已受有效角色条件保护，按实际必要性修复并记录差异。

## 交付边界

- API 请求/响应、数据库结构和前端生成类型不变，无本轮迁移。
- 保留禁用角色绑定与部门引用保护，保留 API Token 的独立授权模型。
- 不处理其他历史 TypeScript 报错，不调整角色管理产品流程。
- 本地证据保存在忽略目录 `server/apps/server/.wrangler/disabled-role-authorization/`，业务生产数据不用于写入测试。

## 执行顺序

1. 固定 dev 基线，保存 TypeScript 诊断并完成前置文档。
2. 并行实现仓储/服务、JWT 缓存逻辑及独立集成测试。
3. 运行定向 Node/Worker 测试、格式检查与 TypeScript 对比。
4. 复盘并修正，完成完整 Node 回归、构建及实际落地记录。
5. 提交 PR，验证 CI，合入 dev 后核对自动部署和只读上线状态。
