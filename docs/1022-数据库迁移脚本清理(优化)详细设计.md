# 数据库迁移脚本清理详细设计

## 背景与边界

现有 PostgreSQL 支持在独立开发分支实施。本轮只整理数据库工具，不执行线上迁移，不改变业务表、种子数据或已发布 SQL。已有数据库必须继续保有原升级路径。

当前存在三套不同用途的 SQL：`apps/server/d1-migrations` 是 D1 编号迁移账本；`packages/core/src/db/migrations` 是早期无账本的 SQLite 升级资料；`apps/server/postgresql-migrations` 是 PostgreSQL 独立迁移。历史文件不能按内容相同或编号重复直接删除，D1 记录的是迁移文件名。

## 清理方案

1. 停用 `db:init node migration` 的无账本批量重放。参数必须在打开数据库、加载配置或同步种子前拒绝，并给出当前本地迁移命令及文档。早期 SQL 保留供旧版本定向升级与回归测试使用，标记为历史资料。
2. 初始化命令只负责新库初始化；Worker 的兼容 migration 参数继续转交 Wrangler 官方账本。移除 Worker 全量初始化中不再可达的旧增量分支，更新帮助说明。Node 初始化结构失败即退出，避免继续种子同步掩盖结构失败。
3. 全量 DDL 生成器不再删除历史迁移目录。使用本次调用独享的临时目录，先完成所有领域生成再更新 DDL；生成失败必须返回非零，不输出完成。旧增量生成参数拒绝执行，防止继续写入无账本历史目录。生成和初始化均不自动执行升级。
4. 保留部门、角色、资产的受控 Node 迁移（事务、校验值、成功标记）及 D1 0015–0017 待发布升级；保留本轮 PostgreSQL 工具。通过统一说明区分新库 DDL、旧库迁移、种子同步以及各数据库命令。

## 验证与恢复

测试隔离临时文件，覆盖生成成功不改历史、生成失败不提前覆盖 DDL、旧参数拒绝且无数据库/种子副作用，以及现有 Node/D1 迁移回滚与重复执行回归。变更前后比较根目录与应用 TypeScript 诊断，执行格式检查、定向测试、Node 构建和 `git diff --check`。SQL 历史以哈希比对保持原字节，工作区已有 PostgreSQL 改动完整保留。

本轮回退仅需还原工具和说明的 Git 改动，不涉及数据库回滚。未来若要压缩历史迁移，必须另设新库基线与旧库截止版本，完成存量升级后再设计；本轮不折叠迁移账本。
