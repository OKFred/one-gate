# 0801-移动端管理(功能)实际落地

| 模块/功能 | 计划内容 | 实际落地 | 差异说明 |
| --- | --- | --- | --- |
| **设备管理 (Device)** | 后端 `Device` 增删改查及设备表结构；前端 `TheTable` 及 `TheForm`。 | 已完成 | **少改**：前端去除了“同步(Sync)”操作。理由是后端并没有需要单独提供同步的API，移动端的数据同步是通过MQTT自动下发的。 |

## 2. 规范性与 TS 类型复盘 (复盘次数：3次)

在此次开发期间，一共进行了 **3 次复盘校验循环**，主要排除了以下出入及 TS 报错：

1. **第一次复盘**：发现前端 `async-task` 表格的 `form` 配置缺失（`SchemaCrudPage` 在部分条件下强制要求有 `form` 定义），以及 `async-task` 的 `businessKey` 原为 `admin.app`，已修改对齐。
2. **第二次复盘**：跑全局 ESLint 及 TypeScript 时，暴露了 MUI 的 `Drawer` 组件 `PaperProps` 不兼容问题，以及 `Switch` 导入源错误，通过转换为 `sx` 和修复引入为 `@mui/material` 解决。此外，移除了未使用到的 `extraContext` 及 `SyncIcon`。
3. **第三次复盘**：修复了 `isEdit` 被断言为 `unknown` 等隐患问题，同时加了 `/* eslint-disable react-refresh/only-export-components */` 以解决前端热更新警告。

## 3. 后续建议与 TS 报错收尾

经过多次复盘修改，目前 `platform/apps/admin/src/pages/mobile/*` 目录下本次修改和新增的所有文件，均已完全通过 `pnpm run lint` 和 `pnpm run format`，并且没有任何因为本次新增逻辑引发的 TypeScript 错误。

**后续建议**：
1. **MQTT 发送及回调确认**：目前前端虽然已有了设备关联及相关异步任务（AsyncTask）的展示功能，但真实的设备状态推送依赖于真实网关和客户端接入，后续需要通过真实的端对端 MQTT 上线联调，测试前端轮询或 WebSockets 接收到 `last_sync_time` 变化后的体验情况。
2. **鉴权路由补齐**：后端封装好后，可以检查并分配这些新菜单的 RBAC 角色权限给当前管理员账户，以便在生产环境中显示左侧菜单（如未配置 `Menu` 表，移动端管理的左侧菜单可能不会显示，当前可通过手动跳转 URL `/admin/mobile/app` 进行 UI 测试）。
