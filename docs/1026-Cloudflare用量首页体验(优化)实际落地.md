# Cloudflare 用量首页体验优化：实际落地

## 页面变化

- 用量首页不再重复显示大欢迎区、长同步告警和多层账单行项。默认展示账号与更新时间、同步状态、已核验额度和需关注项，随后是费用汇总、图表与紧凑指标卡。
- 费用保持币种、账期、费用口径隔离，采用十进制精确求和；费用行项和解释收进“费用明细”。未知费用不当成零。
- 来源、原始原因、完整周期与重置时间通过指标详情弹窗查看。完整指标表、覆盖范围及调度信息默认折叠。未知额度、估算、过期、旧周期和占用告警仍直接可见。
- 图表前移，加入 1／3 天并保留 7／30 天。范围按 UTC 自然日，仅筛选趋势，不改变卡片或账单各自的统计周期。
- 日用量使用折线和当前每日额度参考线；账期／月用量使用真实累计观测，容量只显示当前点。80% 为预警线，100% 明确内含量／硬上限／容量；未知、过期、未来时间或周期未核实的数据不画额度线。
- 缺失日期和 null 断线。累计观察未积累时只显示当前点，不补造历史；自然月参考聚合单列“账期尚未核实”，不会承诺形成已核实累计曲线。

## 数据与实现

前端拆分展示、格式化和纯图表变换，沿用 MUI 主题与中英文文案，没有新图表依赖。保留原请求封装、会话隔离与刷新限流；增加读取失败后的显式重新加载。

后端 days schema 与生成的 OpenAPI 同步为 1／3／7／30，旧请求兼容。使用现有 `cumulative_snapshot` 类型，以 `quota-observation:` 来源按采集日记录可靠的周期累计值；不记录参考月聚合、空值、无效或过期周期，不混加原始 daily 和 API 累计。

相较初始计划，多补了跨日覆盖保护：API 的原始累计日期可能仍指向旧的 ChargePeriodStart，不能覆盖已经保存的采集日观察。发布前按主键去重，UPSERT 保留观察优先级，新观察可同日更新。14 行分块最多 91 参数，继续低于 [D1 官方的 100 参数上限](https://developers.cloudflare.com/d1/platform/limits/)；单 batch、租约 fencing、失败退避与历史清理保持。

无新增数据库字段或迁移，无权限、菜单、部署 Secret 或供应商额度规则变化；其他业务表不迁移。月度曲线从启用后的观测逐日形成，不把既有缺口当作零。
