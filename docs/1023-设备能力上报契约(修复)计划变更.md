# 设备能力上报契约修复计划变更

## 文件范围

| 文件                                                            | 计划                                                     |
| --------------------------------------------------------------- | -------------------------------------------------------- |
| `server/packages/admin/src/mobile/device/domain/device.ts`      | 定义固定可报告操作清单，替换宽泛类别正则为精确成员校验   |
| `server/packages/admin/src/mobile/device/domain/device.spec.ts` | 合法清单、历史兼容和异常输入的正反用例                   |
| 设备报告 HTTP 集成测试                                          | 覆盖合法报告、稳定 422 及错误时不写快照                  |
| `server/apps/server/src/mobile-ops-session.workers.spec.ts`     | 新增报告能力仍不能通过运维通道执行，无命令转发和审计记录 |
| 本目录实际落地文档                                              | 记录最终实现、验证与剩余生产验收                         |

## 顺序和边界

1. 确认客户端 15 项能力和服务端执行白名单 10 项的不同用途，记录设计。
2. 保存相关测试基线：Node 3 文件 / 36 测试通过；沿用本轮最新 TypeScript 0 错误基线。
3. 修改领域校验并补正反测试；格式化后对比 TypeScript 诊断，进行复核。
4. 执行 Node/workerd 聚焦回归；发布方统一构建、打包、提交推送和发布。
5. 由客户端对话进行真实进程重启和脱敏验收，补落地结果。

不修改 Durable Object 执行白名单，不增加未知命令执行、shell、动态能力名或通配授权。服务端报告认证与数据写入路径保持现有机制。
