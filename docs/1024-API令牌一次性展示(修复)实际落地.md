# API 令牌一次性展示修复实际落地

## 实际变更

与计划一致：管理页改为读取 `response.data.data.rawToken`，参数与响应使用现有 API
封装的类型推导，移除该页三处 `any`。已有弹窗在创建成功时显示一次，关闭时清空组件内明文。
后端哈希存储、权限、令牌生命周期及接口合同均保持原实现。

新增独立的模拟浏览器 fixture 和三项回归，并将 `api-token/` 纳入现有前端 CI：

- 实际嵌套成功响应打开一次性弹窗；关闭、重新打开创建表单及刷新均不再次显示原文。
- HTTP 200 且 `ok:false` 不显示响应中的令牌，不自动重试写入。
- HTTP 503 不显示响应中的令牌，不自动重试写入。

全部请求在本地浏览器测试中被 mock 拦截，只使用明确的虚构凭据。

## 验证与复核

- 管理员应用 TypeScript：修改前后均为零错误。
- E2E 类型检查：修改前后通过。
- 管理员前端构建通过；定向 Playwright 回归 **3/3 通过**。
- 变更代码 ESLint、Prettier、UTF-8 无 BOM、LF 和差异空白检查通过。
- 完成 **1 轮**独立复核，无待修正问题或新增 TypeScript 诊断。

## 发布与验收边界

仅需发布管理员前端，数据库、后端及采集服务无需随本修复变更。PR 检查和实际发布结果单独记录。
线上凭据创建由操作人完成；该浏览器回归不创建生产令牌。

已经错过且没有安全保存的令牌原文不能通过数据库哈希还原。后续如需替代令牌，应由操作人明确创建和保存，
再按业务流程处理旧令牌与企业授权。本次没有增加明文持久化或找回接口。

后续可扩展凭据创建场景的会话切换与列表刷新失败回归；现有修复不依赖这些扩展。
