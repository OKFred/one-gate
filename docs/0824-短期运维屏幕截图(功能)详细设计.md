# AutoJS6 短期运维屏幕截图详细设计

## 背景与边界

现有短期运维通过 `ops/v1` MQTT 唤醒设备建立临时 WSS，并仅开放固定的结构化操作。新增截图能力继续沿用该通道，不进入普通 MQTT 业务任务队列，不启动 AutoJS 引擎，也不暂停、抢占或操作前台业务任务。

截图仅服务于当前浏览器会话：图片不写入 D1、R2、日志或审计密文。审计只保留操作、结果、尺寸、摘要、耗时和传输字节数。Android `FLAG_SECURE` 内容遵守系统限制，不尝试绕过。

## 协议设计

新增只读操作 `device.screen.capture`。协议版本和 WebSocket 子协议保持 `1` 与 `autojs6-ops-v1`，通过能力列表做加法兼容；旧客户端未声明该操作时管理端禁用按钮。

JSON 控制帧继续限制为 64 KiB。截图使用单个二进制制品帧，PNG 最大 16 MiB：

```text
uint32be(headerLength) | UTF-8 JSON header | PNG bytes
```

Header 固定包含 `protocolVersion`、`type=artifact`、`sessionId`、`requestId`、`operation`、`artifactId`、`mimeType`、`sizeBytes`、`sha256`、`width`、`height` 和 `capturedAt`。设备先发送二进制制品帧，发送成功后再发送普通 JSON 终态响应；浏览器只有在收到匹配的成功终态并通过摘要校验后才展示图片。

## 手机端执行

Termux Node 客户端以固定低优先级命令 `su -c "nice -n 10 screencap -p"` 获取 PNG，不接受远程命令文本或截图参数。执行器使用独立的有界二进制命令接口，校验 PNG 签名、IHDR 尺寸、16 MiB 上限和 SHA-256。

截图按只读运维操作执行，允许与前台业务任务并行；同一会话最多一个截图在途。捕获限时 10 秒、完整请求限时 15 秒。WSS 已有发送积压时直接返回 `SCREENSHOT_TRANSFER_BUSY`，避免继续占用内存和网络。

稳定错误码包括 `SCREENSHOT_UNSUPPORTED`、`SCREENSHOT_CAPTURE_FAILED`、`SCREENSHOT_FORMAT_INVALID`、`SCREENSHOT_TOO_LARGE`、`SCREENSHOT_TRANSFER_BUSY` 和 `SCREENSHOT_TRANSFER_FAILED`。

## Durable Object 与审计

Durable Object 保持文本控制帧原有限制，只允许设备角色发送二进制帧。收到截图制品时解析并校验 Header、总长度、会话身份和关联审计记录，确认其对应一个执行中的 `device.screen.capture` 请求后才转发给操作员。

图片正文不写入 Durable Object Storage 或 D1。二进制转发时只累加审计的 `response_bytes`；随后终态 JSON 继续按现有 AES-GCM 规则加密保存元数据。非法、超限或无法关联的制品会被拒绝，并尽可能将对应审计终结为失败。

本功能不新增 HTTP API、数据表、迁移、对象存储配置或 PC 代理。

## 管理端

设备运维面板连接后读取 `hello` 或 `device.ops.capabilities`，只有设备声明 `device.screen.capture` 时启用“获取截屏”。点击后生成唯一请求 ID并进入加载状态，禁止重复截图。

浏览器将 WebSocket `binaryType` 设为 `arraybuffer`，解析二进制 Header，复核长度和 SHA-256，再创建临时 Blob URL。成功后在弹窗中自适应预览并提供 PNG 原图下载；新截图、设备切换、会话关闭或组件卸载时撤销旧 URL。

## 验证与上线

开发与自动验证期间不调用任何 ADB 命令。手机端使用模拟 PNG 和模拟 WSS 验证执行、并发、超限、超时及前台任务状态不变；Worker 测试验证二进制转发和审计边界；管理端通过类型检查、构建和组件逻辑测试验证预览生命周期。

Pixel 5 真机验收保持待执行，只有用户明确说明 ADB 已空闲并授权后才开展。上线顺序为 Node Server 与管理端先上线，再发布支持截图的 mobile 客户端并执行能力门控金丝雀。
