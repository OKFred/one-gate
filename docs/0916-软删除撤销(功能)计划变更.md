# 15 秒撤销删除计划变更

## 基线

- 分支：`codex/soft-delete-undo`，基于最新 dev `2ed0ba6a`。
- 工作区已有未跟踪 `NUL.log`，保持不动。
- 编码 UTF-8 无 BOM、LF；不修改规范文件，不新增 any，不修改数据库结构或默认值。
- 改动前类型诊断保存在被忽略的 `server/apps/server/.wrangler/soft-delete-undo/`。

## 预计改动

| 子系统                                      | 计划内容                                                       |
| ------------------------------------------- | -------------------------------------------------------------- |
| core 公共软删除/回收站合同                  | 15 秒窗口、公共收据、可选 undo 能力                            |
| admin 部门 model/repository/service/adapter | 版本化删除响应，数据库执行时限与本人条件，业务删除权限及失败码 |
| admin 回收站 model/service                  | 通用已认证 undo 路由，不依赖回收站恢复权限                     |
| 后端翻译及测试                              | 失败文案，SQL/权限/接口双驱动回归                              |
| UI Notification                             | action、执行状态、更新/关闭句柄、到期与失败展示分离            |
| UI API 层                                   | 可选局部错误展示、稳定错误分类、撤销及新删除封装、生成 OpenAPI |
| UI 公共撤销协调器                           | 身份隔离、期限、失败状态、手动重试、资源变更通知               |
| 部门树                                      | 新删除入口、接入公共浮窗、查询乱序及卸载保护                   |
| 前端翻译及 E2E                              | 中英文，倒计时、权限、冲突、未知结果、恢复成功后刷新失败       |

## 实施顺序

1. 保存本设计/计划和类型基线。
2. 并行实现后端合同与 SQL、前端公共能力及部门接入、隔离 UI 测试。

4. 对变更文件格式化，运行类型对比与相关测试，再进入正式复盘；发现需修正先暂存，最多五轮。
5. 完成相关构建与 git diff --check，填写实际落地文档，分开列明本地代码验证和未执行的上线验收。
