## 实际行为

- 全局错误处理在 SQL 通用归类前检查最多 6 层 cause，以固定供应商消息识别 D1 每日读取、每日写入及存储容量；支持真实 DrizzleQueryError 的底层 cause。
- KV 明确历史每日额度文本与 `KV GET/PUT/DELETE/LIST failed: 429 Too Many Requests` 分开，后者只提示请求受限，不认定每日额度用尽。KV 每日文本属于历史格式兼容，不能保证供应商所有未来错误措辞都已覆盖。
- Workers 明确运行时资源消息可由后端识别；1027 每日请求及 1102 CPU/内存边缘错误页由共享请求层识别，要求诊断头或严格 Cloudflare 页面结构。未虚构后端可以捕获应用执行前被平台拒绝的所有错误。
- 七个固定码使用 `CLOUDFLARE_` 前缀；额度/容量/执行资源返回 503，KV 短期限流返回 429。保持 `{ok:false,message,data:{code,details:[]}}`，保留 `x-request-id`、元数据日志，限额响应 `private, no-store`。
- 已识别限额的响应直接使用随代码发布的中英文安全文案，不调用 D1/KV 翻译。后端种子登记同源词条，但运行提示不依赖同步种子。
- 共享请求层同时处理 HTTP 错误和 HTTP 200 + `ok:false`；本地中英词条在登录阶段可用。旧服务返回 `errorHandler.unknownError` 时显示服务暂不可用，不凭空诊断 D1 限额；普通 429/5xx 显示通用友好提示。
- 断网/CORS 无可读响应时只说明网络或服务暂不可用，提示持续故障时联系管理员检查额度及服务；不声称已确认具体平台限额。原认证、TOTP、身份隔离、局部展示门控保留，无自动写请求重试，503 仍属于操作结果未知。
- 不透传 SQL、参数和原始供应商响应；移除共享请求层开发态任意错误数据输出。

## 与计划的差异

全路由 429/503 OpenAPI 响应枚举按实施范围确认延期，没有新增业务路由、请求字段或错误数据结构，因此未进行全量类型重生成。其余目标与计划一致。
