# 内建 TOTP 后置门禁计划变更

## 目标

将 Hodor 浏览器认证调整为“密码/GitHub/飞书/one-sso 主认证 → TOTP → 系统”，并在生产
验收后用内建门禁替换 Hodor 的 Cloudflare Access 邮箱验证码。

## 计划变更

1. 新增 TOTP 领域、应用、基础设施和 HTTP 接口，实现 RFC 6238、Token 绑定 Cookie、重放
   阻止和限流。
2. 新增 SQLite-backed Durable Object binding/class migration；Node 使用同契约的内存适配器，
   不修改 D1。
3. 将 Access 路由分类改为运行时无关的认证路由策略，明确主认证、门禁控制、机器和 WebSocket
   白名单。
4. 用 TOTP 门禁中间件替换 Cloudflare Access Origin JWT 校验，并统一结构化安全日志。
5. 新增三个 POST 接口：`gate/status`、`gate/verify`、`gate/logout`，同步 OpenAPI 类型。
6. 将 admin 登录与 OAuth/SSO 登录回调改为只保存 Hodor Token；新增共享门禁状态机，TOTP
   成功后再加载菜单和权限。
7. 让 enterprise/personal 在完成两阶段认证后再接收现有跨应用登录返回；显式退出同时清理
   Hodor 登录态和门禁 Cookie。
8. 新增离线登记脚本，生成 `.secrets/totp-gate.<environment>.env` 和 QR/动态码 HTML；真实
   Secret、Cookie 和验证码不进入 Git、日志或 Playwright state。
9. 删除 Hodor Access 运行时配置和 CI Secret 上传项，新增 `HODOR_TOTP_GATE_SECRET`；生成最新
   Wrangler 类型。
10. 增加领域、应用、HTTP、Durable Object、路由策略、前端状态机和日志脱敏测试；完成 Windows
    构建、定向 Vitest、Linux CI 和生产浏览器验收。
11. 最多五轮复盘后补充同名实际落地文档，记录代码、测试、提交、部署和外部清理的真实边界。

## 公共接口兼容性

- 现有登录、OAuth、SSO、设备、MQTT 和 WebSocket 请求响应保持不变。
- 登录成功后的前端导航时机改变：主认证后停留在 TOTP 阶段。
- 未通过 TOTP 的 Hodor Token 不能调用用户业务接口。
- 不修改 one-sso、不修改用户数据和 D1 Schema、不增加外键。

## 验收条件

- 四种已实现主认证方式成功后均停留在 TOTP 阶段。
- SSO 登录回调前后无菜单、权限或业务数据请求。
- 当前 Token 对应的 TOTP 验证成功后才进入系统；换 Token 后旧 Cookie 失效。
- 验证码重放、限流、Cookie 篡改、退出和配置缺失行为符合详细设计。
- 机器回调、设备上报和 WebSocket 不受浏览器门禁影响。
- 生产移除 Hodor Access 后，one-sso → TOTP → Hodor 登录完整走通，日志含 requestId 且无敏感数据。
