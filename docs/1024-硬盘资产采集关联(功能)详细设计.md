# 硬盘资产采集关联详细设计

日期：2026-10-24。基线 `7ea08c7e`，新分支 `codex/hardware-asset-linking`。上轮维护与设备修复尚在独立开发分支，本轮保留已验证代码作为开发基线，不改变 main 或线上版本。

## 现状与目标

One Gate 已有资产、标识、安装归属和测点绑定四表，并支持原子 A→B 安装关系变更。现有 mapping 接口以采集器、设备和指标键查绑定，缺少硬件身份目录。oneMiniHouse 的 SMART helper 对路径、型号和 SN 使用固定读取白名单，公共缓存故意不含私有身份；ingestor 当前哈希不完整覆盖任意关联 lineage。

本期打通硬盘稳定身份到逐指标关联，验收采用合成模拟。资产主数据统一由 One Gate 管理；采集端缓存只读目录并固化采样时关联，Grafana 按资产 UUID 展示连续历史。接口见同目录《接口契约》，该文件是两边协作基线。

## One Gate 实现

1. 在资产域增加 telemetry 子路由，提供 catalog 与 resolveBatch。请求/响应 schema 仍集中声明，不能在 service 内硬编码 properties。
2. 新增纯 telemetry 身份解析模块及规范化、canonical revision 函数；不跨包导入业务私有 repository。
3. SQLite/D1 和 PG 各自以单条有界查询读取目录和权限，避免分页混合快照。现有四表不变，无新增数据库默认值或结构迁移。
4. 新增专门 telemetry:read 权限，SQL token guard 使用固定服务端权限，保留既有 mapping token 行为。token 的企业 grant 和有效 owner 继续生效；敏感标识不随旧 mapping 权限下发。
5. 管理员继续用现有资产标识和安装记录页面完成一次登记/迁移；为采集用户补硬盘接入操作说明，UI 必要时补协议封装，不重建资产管理页面。
6. 新路由同步业务类型、权限种子、后端错误翻译和 OpenAPI；只在隔离测试库进行初始化，不操作生产数据。

## 采集端职责

由真实对话“从iot数据采集开始”负责 oneMiniHouse/private-public 仓库，One Gate 实施者不直接修改其现有队列及健康展示工作。该对话负责私有硬件身份采集、本地目录客户端/缓存、逐指标冻结、幂等哈希投影和 Grafana 查询。其额外实施前置文档遵循自身仓库指导。

目录的 SN/WWN 保持在受限控制面；公共温度缓存与 MQTT 只携带资产 UUID 和关联状态。资产读取身份与硬件访问权限分开，模拟器不会放宽现有 root helper 白名单。

## 历史与失败

安装区间采用半开区间，精确 T 边界可重复测试。身份表没有历史区间，因此未固化的旧观测在身份最近修改时间之前保持未知；首次登记应早于采样。已冻结消息不按新目录重新归属。

空、重复、弱身份或桥接器歧义不猜测。身份未知、目录过期、主机不匹配保留有效测值并标记关联未知；不会导致误归盘、丢整条遥测或以 0 代替温度。

目录访问失败遵循原 TTL；收到明确拒绝停止新关联。控制面离线时撤权最长存在 15 分钟识别窗口，该限制公开记录。

## 验证层次

- 纯规则：WWN/SN、型号、冲突、时间边界、退役、内容哈希、目录过期。
- 持久化/API：真实 SQLite、workerd D1、PG；新增权限及旧 mapping 权限隔离、token撤销、租户隔离、一致快照和上限。
- 跨仓库模拟：真实 One Gate 本地 API + 采集模拟器，真实创建 A/B/D/E 和执行 assign；冻结队列重放；验证资产视图历史连续及配置哈希未变。
- 代码：格式、修改前后 TypeScript 对比、相关测试、Node构建、Worker dry-run、diff-check。

结果分为契约、单仓测试、跨仓库模拟及未来真实设备验收，不能将模拟通过写成实盘迁移成功。本轮没有提交、推送、合并或部署授权的新增推定；完成后交付可审阅结果。
