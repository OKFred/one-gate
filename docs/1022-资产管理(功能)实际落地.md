## 实际功能

- 企业和成员：平台显式创建/启停企业；企业内 `owner/admin/editor/viewer` 固定能力，成员管理、原子所有权交接、最后有效所有者保护，以及全局账号停用后企业冻结和平台带原因恢复。
- 企业独立台账：资产 UUID 不随名称、资产编号、安装主机、退役或重新启用而改变。资产编号按企业唯一，名称允许重复，缺少 SN 可以登记。
- 硬件标识：SN、WWN、GPU UUID、SID 和其他标识分别标准化，保留来源和可信度；已核验标识按企业唯一，拒绝空值和厂家占位值，不自动合并资产。
- 安装与测点：半开有效区间，历史重叠检查，结束旧关系和新建关系在同一事务中完成；按原始观测时间解析迟到数据。退役结束当前关系并保留历史，重新启用不重开旧关系。
- 机器读取：认证主体明确区分用户和 API Token，Token 必须显式绑定企业并具有 `enterprise.asset.mapping:read`。不继承创建者的企业资格，只返回最小映射投影。
- 企业页面 `/enterprise/tenant`，台账页面 `/enterprise/asset`，含企业选择、查询分页、资产详情、标识、关系历史、测点解析、成员和机器授权；同步中英文、菜单、权限和生成的 OpenAPI 类型。

授权为系统 RBAC 与当前企业能力同时满足。平台超级管理员也不能跳过普通资产接口的成员条件。每次读取及最终写 SQL 均带企业与当前有效权限条件；资产的企业不可编辑，跨企业和不存在的记录使用相同不可用结果。

前端隔离同时使用登录会话、企业选择代次和查询顺序，切换企业/身份后清空详情、表单及确认框，丢弃旧响应。写入结果与列表刷新结果分别处理，刷新失败不改变已成功写入的结论。

## 与计划的差异和边界

1. 结构迁移使用 `0016_enterprise_assets.sql`；额外补充 `0017_enterprise_asset_metadata.sql`，使已有部署自动获得菜单、7 项权限和后端错误翻译。新菜单使用 108/109，保留原回收站 107；保留无关菜单及普通角色的原权限，不自动授予普通角色新权限。
2. Node 一次性脚本在同一事务中执行 0016 和 0017，使用一个成功标记及两份 SQL 的联合校验值；D1 使用 Wrangler 官方账本，两个编号分别原子应用。0017 失败时 0016 可能已经成功，须保持维护状态，修复元数据冲突后继续完成余下迁移。
3. 所有 7 张新表均无数据库默认值，时间、状态和审计由服务端显式写入。增加 `state_reason` 保存退役/重新启用原因。
4. 已结束历史保持只读。首期支持补录不重叠历史、迁移当前关系、结束当前关系，不覆盖已封闭的原始历史；复杂历史纠错的版本链留待单独迭代。
5. 主机自身只登记位置，不允许主机嵌套安装；主机退役前必须处理仍在其上的资产。首期没有资产硬删除、30 天物理清理或全局回收站注册。
6. 页面验收同时修复企业应用自身的 scope 默认值，以及共享菜单对 `/enterprise/` 前缀的识别，保留现有 `/biz/` 路径支持。请求层新增可选的错误展示作用域检查，其他请求的默认错误行为及认证/二次验证流程维持原行为。

采购、折旧、财务账套、自动发现、跨企业转让、SSO 自动入企、原始遥测、MQTT、PG/Supabase 实际同步未纳入本期；原有 enterprise 考勤、工作流和 EDM 不随本期自动获得租户隔离。

## 使用与发布说明

1. 平台管理员通过“企业与成员”创建企业，指定已有系统用户作为首位所有者。给业务用户分配必要的系统权限，例如企业读取、资产读取及相应新增/编辑；历史测点解析还需要映射读取权限。企业内部角色继续限制其最终能力。
2. 企业所有者/管理员管理成员和机器授权。绑定机器令牌时输入本人创建、已赋予映射读取权限且当前有效的令牌 ID；页面不显示令牌原文或哈希。一个令牌只绑定一个企业，停用授权立即影响后续数据库读取。
3. 在资产台账先选择企业再登记资产；维护标识、安装/测点关系时填写真实生效时间和原因。已结束关系只读；设备换主机时使用迁移操作，保留资产身份。
4. 上线前备份并安排维护窗口暂停相关写入。Node 已有数据库在 `server/` 目录执行 `pnpm run db:migrate:assets:node --database=<现有本地 SQLite 文件的绝对路径>`；脚本拒绝远程 URL、相对路径和缺失文件。新库走初始化，不对已初始化但没有迁移标记的新库重复运行旧库升级脚本。
5. Worker 使用现有 D1 官方迁移流程，确认 0016 和 0017 均完成，再运行完整结构契约。完成代码部署及权限缓存刷新后，用两家测试企业验收隔离、成员能力和只读机器授权，再恢复相关写入。不要以本地演练代替生产验收。
6. 迁移失败保持维护状态，依据账本和结构排查；Node 失败回滚，D1 依据已成功编号继续。新版创建了真实资产后不能直接删表回退，应保留新增表与记录，或在停写下恢复经过核对的备份。旧版本代码不会管理新资产。
